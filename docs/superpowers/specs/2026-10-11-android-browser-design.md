## 1. 产品定位

### 1.1 一句话定位

**Aurora 是一款「全能功能型」安卓浏览器：在单手可及的界面上，把标签管理、拦截、阅读、下载、书签、扩展这些能力收进一个克制的深色界面里。**

### 1.2 目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 重度多标签用户 | 通勤、查资料、比价 | 几十个标签不乱、能分组、能恢复 |
| 隐私敏感用户 | 日常浏览 | 看得到拦截了什么、能控权限 |
| 内容阅读者 | 长文、新闻、小说 | 阅读模式、字号调节、夜间护眼 |
| 资源下载用户 | 视频/文档/安装包 | 后台下载、断点续传、好找 |

### 1.3 设计原则

1. **单手可达优先**：所有高频操作落在屏幕底部 1/3。顶部只放「看」的信息（地址、站点身份），底部放「做」的动作。
2. **功能全，界面静**：能力很多，但默认只呈现一个地址栏 + 一条底部工具栏；其余能力收进菜单面板与二级页面。
3. **深色是第一公民**：以 OLED 深色为默认主题，浅色是派生主题，两套都由语义 token 驱动。
4. **状态永远可见**：加载进度、拦截计数、无痕标识、同步状态都在界面上有明确位置，不做「静默魔法」。
5. **不做装饰性动画**：每屏最多 1–2 处动效，全部尊重 `prefers-reduced-motion` / 系统「移除动画」。

### 1.4 非目标（本期不做）

- 桌面端 / iOS 端
- 自研渲染引擎
- 内置 AI 助手（预留在菜单占位，不在本期范围）
- 账号体系后端实现（只定义 UI 与状态位）

### 2.3 间距 / 圆角 / 高度

- **间距节奏（4/8dp）**：`--space-1:4` `--space-2:8` `--space-3:12` `--space-4:16` `--space-5:24` `--space-6:32` `--space-7:48`
- **圆角**：`--radius-xs:6` `--radius-sm:10`（按钮/输入）`--radius-md:14`（卡片）`--radius-lg:20`（面板/底部工具栏）`--radius-xl:28` `--radius-full:999`（胶囊）
- **最小触摸目标**：**48×48dp**（Android），图标视觉尺寸 24dp，不足时用透明内边距外扩命中区。
- **相邻触摸目标间距**：≥ 8dp。
- **安全区**：底部工具栏与顶部地址栏必须应用 `WindowInsets`（状态栏 + 手势导航条），任何可点内容不得压在手势条 / 挖孔下。

深色下靠「亮一档的表面 + 细描边」表达层级，阴影为辅。

| Token | 值 | 用途 |
|---|---|---|
| `--shadow-1` | `0 1px 2px rgba(0,0,0,.40)` | 卡片 |
| `--shadow-2` | `0 4px 12px rgba(0,0,0,.45)` | 悬浮工具栏 |

### 2.5 动效

| Token | 值 | 用途 |
|---|---|---|
| `--dur-fast` | 120 ms | 按下反馈、图标切换 |
| `--dur-base` | 200 ms | 面板进出、标签切换 |
| `--dur-slow` | 320 ms | 页面转场 |
| `--ease-standard` | `cubic-bezier(.2,0,0,1)` | 通用 |
| `--ease-decelerate` | `cubic-bezier(0,0,0,1)` | 入场 |
| `--ease-accelerate` | `cubic-bezier(.3,0,1,1)` | 退场 |

规则：入场用 decelerate 且比退场慢；**退场时长 ≤ 入场**；按压反馈在 80–150ms 内出现；按压态只改颜色/透明度/高度，**不得改变布局尺寸**（避免抖动）。系统开启「移除动画」时全部降级为即时切换。

### 2.6 图标

- 库：**Phosphor Icons（Regular，Outline 风格）**，本规格原型已内联真实 Phosphor path。
- 同一层级只用一种风格（线性 or 填充），描边粗细统一。
- 尺寸 token：`icon-sm 16dp` / `icon-md 20dp` / `icon-lg 24dp` / `icon-xl 32dp`。
- 装饰性图标（旁边有可见文字）对无障碍树隐藏；独立图标按钮必须带可访问名称并暴露选中/展开状态。
- **禁止用 emoji 充当结构图标。**

## 4. 导航模型与手势

**底部工具栏（5 槽，拇指区）**：`返回` · `前进` · `主页/新标签` · `标签（带计数角标）` · `菜单`

**顶部地址栏**：左侧站点身份图标（锁 / 盾 / 警告）+ 域名（mono 字体）+ 右侧刷新/停止。

**手势**

| 手势 | 行为 |
|---|---|
| 屏幕左/右边缘向内滑 | 返回 / 前进 |
| 底部工具栏下拉 | 展开标签管理 |
| 地址栏上滑 | 进入 omnibox 聚焦态 |
| 地址栏左右滑 | 切换相邻标签 |
| 长按标签卡片 | 多选：关闭/移动/加入组 |
| 双指下拉（网页区） | 触发刷新 |

**返回键行为**：先退全屏视频 → 再关面板 → 再退 omnibox 聚焦 → 再网页后退 → **网页退到头回首页**（不是退出应用）→ 首页上再双击退出（首次按提示「再按一次退出」）。**不得在第一次按返回键就直接退出应用。**

- 首页（新标签页）不是 WebView 的历史条目，所以「历史退不动了」不等于「没得可退」——还差「回首页」这一步。回到首页时把这个标签的 WebView 连同历史一起释放（`WebViewPool.dispose` + `TabRepository.goHome`），否则被 `clearHistory()` 保留的那条旧记录会让「从下一个页面后退」落回老页面而不是首页。
- 系统返回键与工具栏的后退按钮共用同一段判定（`BackPressDispatcher.onBack(panelOpen, omniboxFocused, atHome, canGoBack)`），两条入口不可能给出不同结果。

## 5. 页面规格

> 每页给出：目的 / 结构 / 关键组件 / 状态。原型对应 `prototype/index.html` 中的编号屏幕。

### 5.1 主页 / 新标签页（01）

- **目的**：启动后的落脚点，3 秒内可发起搜索、接着看上一集、或进入常用站点。
- **结构（上→下）**：状态栏 → 地址栏（胶囊，占位「搜索或输入网址」）→ **「继续观看」卡片列**（有记录时才出现）→ 快捷入口 4×2 网格（带「+」）→ 底部工具栏。
- **「继续观看」**：排在快捷入口**前面**——「接着看上一集」比「再点一个站点」更接近打开浏览器时想干的事。
  - 一行一张卡：标题（单行省略）→ 出处域名 · 剩余时间 → 3dp 进度条。出处取**来源页**的域名而不是流的地址：真实流多半在某个 CDN 上，那个域名用户没见过。时长还不知道时改说「看到 12:34」，不算一个假的剩余时间。
  - 最多露 4 张：再多就把快捷入口挤出屏幕。数据来自 `PlaybackPreferences.resumable()`（见 5.17），最近看的在最前。
  - 右侧「×」**独立可点**，不在整行的合并语义里——嵌套可点目标会让读屏把两个动作读成一个。所以是 `Row[可点的内容块, 删除按钮]`，不是「整行可点 + 里面一个按钮」。看完一集（`onEnded` → `forget`）自动消失，不必手动清理。
  - 刷新时机：**每次回到前台**（`LifecycleEventEffect(ON_RESUME)`）。进度是内置播放器在另一个界面写的，不重读的话，看完一集退回来卡片上还是进去之前的进度。
- **快捷入口图标**：取站点自己的 favicon（`FaviconStore`），取不到才画站名首字母。
  - 三级缓存：内存 → 磁盘（`cacheDir/favicons`）→ 网络。取图两步：先试 `/favicon.ico`，不行再读首页的 `<link rel="icon">`。ICO 容器里的 PNG 抠出来用（`BitmapFactory` 不认 ICO），`apple-touch-icon` 优先（180×180 PNG，比 16×16 清楚）。解码时夹到 128px——显示最大也就 52dp，没必要把原图整张留在内存里。
  - **只向站点自己发请求**，不用第三方图标服务：那种服务会把「谁装了哪个浏览器、常去哪些站」留在别人的日志里。图标是锦上添花，取不到就退回首字母块，不转圈也不报错。
- **组件**：`OmniboxBar`、`ResumeCard`、`ShortcutTile`、`BottomToolbar`。
- **状态**：空（无快捷入口 → 显示引导「添加常用网站」；无观看记录 → 整块不出现，不留空标题）、无网络（顶部细条「当前离线，显示缓存内容」；图标取不到时保持首字母）。

### 5.2 地址栏聚焦态 / Omnibox（02）

- **目的**：输入与快捷动作。
- **结构**：地址栏展开为输入框（自动聚焦、键盘弹出）→ 建议列表（搜索建议 / 历史 / 书签，行首用类型图标区分）→ 底部快捷动作行（扫码、语音、粘贴并前往、无痕）。
- **组件**：`OmniboxInput`、`SuggestionRow`、`QuickActionRow`。
- **状态**：无输入（显示剪贴板建议 + 热门站点）、有输入（建议实时刷新）、空结果。

### 5.3 网页浏览（03）

- **目的**：内容主体。
- **结构**：顶部地址栏（站点盾牌 + 域名 + 刷新）→ 顶部 2dp 加载进度条 → 内容区 → 底部悬浮玻璃工具栏（返回/前进/主页/标签/菜单）。
- **组件**：`SiteIdentity`、`ProgressBar`、`FloatingToolbar`。
- **状态**：加载中（进度条 + 停止按钮）、加载完成（刷新按钮）、证书警告（地址栏变警告色 + 页面拦截页）、离线（错误页）。
- **点地址栏顺手复制网址**：网页里没有「复制链接」这个入口——桌面浏览器靠右键菜单，移动端长按链接复制的是链接本身，「把当前这一页的地址拿出来」在网页里根本没有对应操作。所以这件事只能由浏览器给，位置就放在地址栏：点一下即复制当前页地址（`UrlClipboard`，`text/plain`，带签名参数的地址原样保留），提示「已复制当前网址」，同时照旧进入 5.2 的输入态。地址为空（主页 / 无痕首页）时不复制、也不提示——用户剪贴板里可能正放着他要粘的东西，一个空地址把它冲掉是最烦人的那种「顺手帮倒忙」。
- **媒体**：页面里的每个 `<video>` 上贴「全屏 / 下载 / 投屏」浮层（见 5.12），菜单里也保留「下载视频 / 投屏」两条入口，给浮层没出现的页面兜底。视频**全屏交给内置播放器**（Media3 / ExoPlayer，见 5.13）：网页里的视频地址普遍是 MSE 的 `blob:` 壳子，把 WebView 交出来的自定义 View 搬到窗口上在真机会黑屏，所以改成从网络层嗅探真实流地址、交给原生播放器用 Surface 渲染。

### 5.4 标签管理（04 / 05）

- **目的**：在几十个标签中快速定位与清理。
- **结构**：顶部「标签数 + 网格/列表切换 + 新建 + 无痕」→ 标签卡片（缩略图 + 标题 + 关闭）→ 网格（2 列）或列表（分组：标签组折叠、普通标签、最近关闭）。
- **缩略图**：预览框里画页面的画面，网格里是大图（`Crop` 裁切）、列表里是小图（48×30dp）。
  - **拍的时机是「页面加载完成之后」**（`WebViewPool.captureThumbnailAsync`），不是打开标签网格的那一刻。网格打开时它自己就盖在网页上了，那一刻去拍只会拍到一个已经切走的画面。拍过的留在池里，切走之后照样显示。
  - **一拍不够，按时间表（400ms / 1500ms / 3000ms）拍三拍，后一拍覆盖前一拍**：`onPageFinished` 与「画面真的画上屏」之间没有保证——实测 400ms 那一拍抠到的仍是一整块底色（页面还没画出来），而只认「第一张拍到的」又会拿到一张画了一半的图（上半个屏幕是页面、下半个还是底色）。拍到就回调一次，时间越晚画面越完整；三拍都没拍到才回 `null`，网格照旧画占位图。
  - **拍法是 `PixelCopy` 抠窗口，不是 `View.draw()`**：WebView 的页面由渲染进程合成，画面不在 View 的绘制列表里，硬件加速下 `draw()` 拿到的是一张空图——这正是缩略图在真机上一直空白的原因。`PixelCopy` 抠的是窗口的合成结果，硬件加速也拿得到。抠之前把叠在网页上的悬浮工具栏那一条（`BottomToolbarHeight`）裁掉，否则缩略图底边挂着一颗胶囊。`PixelCopy` 失败或没有窗口时退回 `View.draw()`，再不行就不存。
  - **只能拍正显示着的那个标签**：`PixelCopy` 抠的是窗口，不管那个位置上是哪个标签的 WebView，所以后台标签加载完成时必须跳过（判据 `isAttachedToWindow`）——少了这一步，后台标签会把当前显示着的那一页存成自己的缩略图。
  - **拍出来是纯色就不当缩略图缓存**：抽样 12×12 个点全同色即判定失败，这一拍当作没拍到、留给下一拍。窗口还没画出页面时抠到的是一整块底色，而空白缩略图比没有缩略图更糟——用户看到的是一块白板。
  - **无痕标签不拍**：网格上照旧画无痕图标，浏览内容也就不落到这张图里。位图只在内存里、随池一起释放（关闭标签即丢），不进磁盘——存下来只是白占空间，还会把浏览过的页面留在设备上。
- **组件**：`TabCard`、`TabRowItem`、`TabGroupHeader`、`ViewToggle`。
- **状态**：空（引导开新标签）、多选（顶部工具条：关闭/加入组/移动）、无痕标签（深黑卡片 + 遮罩图标）、无缩略图（预览框给站点首字母，空白标签给主页图标）。

### 5.8 下载管理（09）

- **目的**：管理进行中与已完成的下载。
- **结构**：分段（进行中 / 已完成）→ 下载行（图标 + 文件名 + 大小/进度 + 操作：暂停/继续/打开/删除）。两个来源合成一张列表：系统 `DownloadManager` 的直链文件，以及 HLS 等流媒体的**离线缓存**（Media3 `SimpleCache`，见 5.13）——后者在副标题里标「离线缓存」，打开时进内置播放器，删的是缓存条目。
- **行内数字**：副标题是「已下载 / 总大小 · 速度」，三者都可能缺，缺的那段整段省略：
  - **总大小**：直链文件由系统下载器给真值；**HLS 拿不到**——`Download.contentLength` 在 media3 1.4.1 里恒为 `C.LENGTH_UNSET`（`DownloadManager` 构造 `Download` 时写死 -1，`DownloadProgress` 里只有「已下载字节」和「完成比例」），分片长度本来也要下完才知道。所以用「已下载 ÷ 已完成比例」反推，前面加「约」。比例低于 1% 时不报——头几个分片和平均值差得远，那时候的数字会往下缩，比不报更让人困惑。
  - **速度**：没有接口能问出来，靠两次「已下载字节」的差除以时间差（`DownloadSpeed`）。样本不足时返回 0，界面按「还不知道」处理，不写「0 B/s」——那看起来像卡住了。字节不变时不记样本，否则「原地不动」的时间会把已有进度摊薄成一个假的慢速度；字节倒退（删掉重下、换源）时旧样本全部作废，不然会算出负数。
  - 总大小还估不出来时改报百分比，否则看不出还剩多少。
- **实时刷新**：下载页开着时每 0.5 秒刷一次，只在真有条目在跑时才查库。以前只在打开那一刻取一次，用户看到的是一个停住的进度条。
- **Referer**：离线缓存的数据源也会带上页面地址（有的 CDN 不带就不给数据），被 401/403 拒了就自动退到不带 Referer 重开——见 [5.16]。`DownloadRequest` 里没有放请求头的地方，所以页面地址记在 `OfflineMedia` 上、由数据源在每次开连接时现取。
- **组件**：`DownloadRow`、`ProgressRing`。
- **状态**：空（「还没有下载」+ 引导）、失败（红色状态 + 重试）。

### 5.12 视频浮层（13）

- **目的**：用户是在**看视频的时候**想下载或投屏的，这时菜单还藏在工具栏后面——要点两下才够得着。所以把三个动作直接贴到视频自己身上。
- **结构**：注入页面的一段脚本给每个 `<video>` 建一条浮层（`position:fixed`，定位到视频右上角，按 `getBoundingClientRect()` 跟随滚动与尺寸变化）：`全屏` · `下载` · `投屏`。视频太小（宽 <96px 或高 <48px）或滚出视口时自动隐藏。
- **为什么不是插进播放器容器**：播放器的父节点十有八九是 `position:static`，插进去会被裁掉，而且容器经常被站点整块重建。
- **状态**：
  - 三个按钮**总是都在**：`全屏` · `下载` · `投屏`。早期版本在 `blob:` 源上只给「全屏」，结果就是用户拿着真机问「为什么没有下载按钮」——按钮缺席看起来像功能没做，不像地址取不到。现在按钮照给，点下去若确实解析不出地址，再用一句提示说清楚原因。
  - `全屏`：把当前进度（`video.currentTime`）一起交给宿主，由内置播放器接着播（见 5.13）。
  - `下载`：拿到真实流地址后分流——播放列表（`.m3u8` / `.mpd`）进离线缓存，直链文件交给系统 `DownloadManager`。
  - `投屏`：把解析出的地址交给能播 `video/*` 的应用。
- **全屏**：按钮不再调 `video.requestFullscreen()`。网页视频普遍是 MSE（`<video>` 的 `src` 只是 `blob:`），WebView 把播放 View 交出来再搬到窗口上这条路在真机上会黑屏；现在只通知宿主，由原生播放器接管画面。
- **回宿主**：浮层通过 `addJavascriptInterface` 注册的单一桥（`AuroraMedia.onMediaAction`）回宿主，宿主校验动作名与地址、并跟当前页面重新提取的视频源比对后才执行。注入的接口对页面里所有脚本可见，不能照单全收。

### 5.13 内置播放器与离线缓存（14）

- **目的**：让「全屏」在真机上真的能看，让流媒体也能「下载」。这两件事是同一个根因的两面：站点把真实流藏在网络层，网页里只有一个 MSE 壳子。
- **嗅探**：`MediaSniffer` 挂在 `WebViewClient.shouldInterceptRequest` 上（这个回调在后台线程），按标签记录见过的媒体地址——播放列表（`.m3u8` / `.mpd`）优先，其次直链文件（`mp4` / `flv` / `mkv` / `webm` / `mov` / `m4v`），分片（`.ts` / `.m4s` / `.aac`）忽略。每标签最多留 24 条，取用时优先 `master.m3u8`（它带各档码率，交给播放器自己选）。换页时清空，免得新页面上点「下载」下到上一个视频。
- **播放**：`PlayerActivity`（Media3 / ExoPlayer + `PlayerView`）。进页面先掰横屏（国内手机默认开着方向锁定，不主动掰就一直是竖的），拿到真实视频宽高后按需纠正为竖屏；沉浸式与 `FLAG_KEEP_SCREEN_ON` 复用 [5.12] 同一套 `ImmersiveMode`。播放失败弹一句可读的原因（`errorCodeName`）再退出，不停在黑屏上。
- **下载**：`OfflineMedia` 用 Media3 的 `DownloadManager` + `SimpleCache`（`DownloadService` 前台服务撑着，切走应用不会被系统收掉）。播放与离线共用同一份缓存，下完就是真离线可播。完成/失败的条目出现在下载页的「已完成」分段里。
- **投屏**：拿到解析后的地址后走 `ACTION_CHOOSER` + `video/*`，与 5.12 一致，不引入 Google Cast。
- **控制层**：不用 `PlayerView` 自带的控制条——它没有清晰度、没有倍速、没有画面比例，也不跟应用的深色令牌一致。自己画一套，布局与手势见 [5.14]。三个二级面板——
  - **清晰度**：从 `Tracks` 的视频组读出各档，按高度去重（同高度留码率最高的一条，HLS 里 avc1 与 hevc 常同时存在）、从高到低排，标签为 `4K / 2K / 1080P / 720P / 480P / 360P`，非标准高度如实写 `${height}P`（540 不能写成「480P」）；读不到高度时用码率 `x.x Mbps`。选中即给视频轨设 `TrackSelectionOverride`，选「自动」则 `clearOverridesOfType(VIDEO)`。
  - **倍速**：0.5× / 0.75× / 1× / 1.25× / 1.5× / 2× / 3×。
  - **画面比例**：适应（FIT）/ 铺满（FILL）/ 裁剪（ZOOM）。
- **手势**：左半屏上下滑调亮度（写 `screenBrightness`，`-1` 时按 0.5 起步）、右半屏上下滑调音量（走 `AudioManager` 的音乐流）、横向拖动看进度（拖动中只显示预览与 `±mm:ss`，抬手才 `seekTo`）、双击左/右半屏进退 10 秒、单击显隐控制层。手势与显示格式的判定抽在 `PlayerGestures` 里，是纯函数。
- **记忆**：播放进度按 URL 存（键用 URL 哈希），下次接着看；**看得不足 5 秒**或**离结尾不足 30 秒**不记——否则下次「接着播」要么等于从头播，要么直接跳到最后几秒，比不记还烦。倍速也记住，且只接受面板上给出的档位。
- **弱网与兼容（v1.1 补）**：硬解初始化失败的机型自动回退软解（`DefaultRenderersFactory.setEnableDecoderFallback(true)`）；`DefaultLoadControl` 放宽到 20 秒起播 / 60 秒上限 / 起播前最少 2.5 秒；HLS 显式建源并打开 `setAllowChunklessPreparation(true)`，起播时不必先拉完整张分片清单。
- **为什么不用系统 `DownloadManager` 直接下 HLS**：`.m3u8` 是一张分片清单，系统下载器只会存下那张几 KB 的文本，用户得到一个播不了的文件。要么在应用内把分片拼起来（等于自己写一个 HLS 下载器），要么交给 Media3 的离线缓存——选后者。

### 5.14 播放器控制层（14）

- **目的**：1.5 只做到「能看」——全屏不黑、能播。真机试完的反馈是「播放效果不太好」，拆成三条：卡顿、画质糊/不能切清晰度、操作太少。这三条都不是引擎选错了（ExoPlayer 的 HLS 支持已是候选里最完整的），缺的是控制层与参数，所以这一节补齐，且不引入新依赖。
- **结构**：控制层浮在画面之上（最深底 + 72% 遮罩），3.5 秒无操作自动隐藏（正在播、面板没开、也没在拖进度时才隐藏）。按钮按**单手能够到的位置**排，不按「功能重要性」排：
  - **左上**：标题，单行省略，宽度只占 60%——给右上那排留位置。
  - **右上**：`小窗` · `投屏`。这两个是同一类动作——把画面交给别处，所以在同一排。
  - **右侧中间**：`下载`。单独占一列，不与中间的播放键抢触摸位置。
  - **中间**：`−10s` · 播放/暂停 · `+10s`。播放/暂停图标自绘（三角形 / 两条圆角竖条）——图标集里没有 `Pause`，为一个按钮引入整套 material-icons-extended 不划算。
  - **右下**：一排 `倍速` · `画质`（只有拿到多档时才出现）· `适应` · `退出全屏`，右对齐。前三个是「调整正在播的这路流」，第四个是「结束」，都是拇指自然落点。
  - **底部**：`当前时间 · 进度条 · 总时长`，在右下那排的**下方**——进度条要占满宽度，不能和 chip 挤一行。
  - 二级面板（倍速/画质/比例）在右下那排的上方展开，玻璃底圆角列表，当前项用品牌色标出。
- **小窗播放**：`PlayerActivity` 声明 `supportsPictureInPicture="true"`，点「小窗」把画面缩成画中画继续播。
  - 宽高比必须先夹紧到系统允许的区间（1/2.39–2.39）：竖屏短剧的比例会越界，越界时 `enterPictureInPictureMode` 直接抛 `IllegalArgumentException`，真机上看起来就是「点了没反应」。尺寸还没拿到时退回 16:9。
  - 入口返回 Boolean，`false` 说明系统/ROM 不放行，给一句提示而不是静默失败。
  - 小窗里**控制层与手势整层让开**（`pip` 状态一到就撤掉），否则会盖住系统自己的展开/关闭按钮。
- **投屏**：把当前播放地址交给能接视频通配 MIME 的应用，与 [5.12] 网页浮层的投屏是同一条路，不引入 Google Cast。
- **下载**：复用 [5.13] 的分流——直链交给系统 `DownloadManager`，播放列表进 Media3 离线缓存。分岔抽在 `MediaDownload` 里，网页浮层、主菜单、内置播放器三处共用，避免各写一遍后漂移。
- **手势提示**：调整过程中屏幕中央显示 `亮度 62%` / `音量 40%` / `12:34 +01:20`，1 秒后自动消失。
- **缓冲与失败**：转圈居中显示（品牌色）；播放失败弹一句可读原因（`errorCodeName` **加上最内层那句真实原因**，如 `ERROR_CODE_IO_BAD_HTTP_STATUS（Invalid response code: 403）`）再退出，不停在黑屏上。
- **点击与拖动的关系**：拖动只在判定出主轴后才消费事件，**抬手不消费**——否则下面那个 `detectTapGestures` 会把单击与双击一起判成手势取消。
- **与 5.12 的关系**：网页浮层的「全屏」把地址与当前进度交给这里；退出后回到网页，页面状态与浮层都还在。
- **建源方式猜错要能自愈**：见 [5.16]。

### 5.15 去广告（前贴片）

- **目的**：去掉视频开头那几秒广告。样本站点 `4kvm.net`（ArtPlayer + 官方 `artplayer-plugin-ads`），播放器容器上写着 `data-preroll-ad-type="image"` / `data-preroll-ad-duration="12"` / `data-preroll-ad-skip-after="6"`——图片广告放 12 秒，6 秒后才允许关。
- **为什么不能只靠域名拦截**：这类广告是**站点自己的页面元素**，由播放器插件渲染，广告图可能就在站点的图片 CDN 上、和正文图片同域。拦域名等于把正文图片一起拦掉，广告却照放（只是变成破图）。域名拦截治的是另一类——广告资源本身在广告网络上的（VAST/IMA）。
- **两层一起做**：
  - **域名层**（`TrackerBlocklist`，67 条）：补了视频贴片广告网络（FreeWheel / SpotX / Teads / SpringServe / Aniview / Connatix / Tremor / Telaria / Sizmek 等）。**故意不拦 `imasdk.googleapis.com`**——它是 Google IMA 的播放器 SDK，不是广告资源地址，拦掉会让用它的播放器整个起不来，代价远大于多看几秒广告。
  - **脚本层**（`AdBlockScript`，注入页面），从最干净到兜底三层：
    1. **剥掉 `data-preroll-ad*` 属性**。属性没了，站点那段代码拿不到广告配置，插件根本不会装——一秒广告都不放，播放器也不会被暂停。前缀只认 `data-preroll-ad`，不认 `data-ad`（那会误伤 `data-address` / `data-adapter`）。
    2. **用 setter 拦下 `window.artplayerPluginAds`**，站点读到的是空壳。它先做 `typeof` 判断再调用，所以空壳必须是函数并返回同名对象。这一层不看时序：注入晚了也有效，只要站点还没读那个全局。
    3. **清掉已经出现的浮层** `.artplayer-plugin-ads`，并**把正片播回来**——插件的做法是「暂停正片再盖广告」，只删浮层会让用户看到「广告没了，画面也不动了」。恢复播放只在同一个播放器容器内进行，不碰页面上其他 `<video>`。
  - 另外清掉无争议的广告位容器（AdSense 的 `<ins>`、广告联盟的 iframe）。
- **注入时机**：第 1 层要赢在时序上，所以脚本在 `onPageStarted` 就注入，不再等 `onPageFinished`——页面脚本在 DOMContentLoaded 时就把属性读走了。这是「尽量早」而不是保证（`evaluateJavascript` 在 `onPageStarted` 可能落到旧文档上），所以 `onPageFinished` 再注入一次，脚本自身的 MutationObserver + 0.8 秒轮询是第三重兜底。脚本幂等（`window.__auroraAdBlock` 守卫）。
- **开关**：复用「隐私与安全」里的追踪器拦截开关——用户心里这就是一件事（拦广告）。
- **拦不住的**：广告和正片在服务端拼成同一条流的（同一份 m3u8，前几个分片是广告）。客户端看到的是一条连续的流，只有解出分片内容才分得出来，域名拦截和元素清理都够不着。

### 5.16 播放失败的通用兜底（1.9）

- **目的**：把「有些视频播不了」从「逐个站点修」变成「一层兜底」。起因是 `4kvm.net` 的实测报告，但修的是这一类问题，不是给那一个站点开后门。
- **样本站点 `https://4kvm.net/play/ch4k8uf4p` 的实况**（全部实测确认，不是推测）：
  - 播放地址由站点自己的 WASM 现算（`build_play_url(dataid, secret_key, quality, play_key)` 签时间戳，`play_key` 取页面里的 `userlink` 当访问令牌），`/video/play` 返回 `quality_urls[]`。1080P 免费；720/480 要 VIP；4K 直接回 `403 4K清晰度仅支持客户端播放，Web端不支持`。
  - 1080P 的播放列表是标准 VOD HLS：`#EXTM3U` / `#EXT-X-PLAYLIST-TYPE:VOD` / 501 个 `#EXTINF`，**没有 `#EXT-X-KEY`、没有 `#EXT-X-MAP`**，所以没有加密、不是 fMP4。
  - 分片后缀是 `.png`、`Content-Type` 是 `image/png`，但内容其实是「**61 字节的 1×1 PNG 头 + 1000 个 MPEG-TS 包**」（H.264 + AAC，ffmpeg 的 `Service01` 在 SDT 里）。这是伪装，**不影响播放**：`TsExtractor.sniff` 会在前 940 字节里按 188 字节间隔找 5 个同步字节，命中后 `skipFully(offset)` 跳过 PNG 头（反编译 media3-extractor 1.4.1 确认）。
  - 分片托管在 `file.icve.com.cn`（阿里云 Tengine），有 **Referer ACL**：`Referer: https://4kvm.net/…` → `403 denied by Referer ACL`；**不带 Referer → 200**；`https://www.icve.com.cn/` → 200。站点自己用 `<meta name="referrer" content="no-referrer">`（盖掉响应头的 `strict-origin-when-cross-origin`）让浏览器不发 Referer，从而绕过这个热链保护。
- **根因**：内置播放器从 1.5 起给每个请求带页面地址当 Referer（为的是另一批「必须带 Referer 才给数据」的站点）。网页里 hls.js 靠 `no-referrer` 播得好好的，我们的播放器反而被每个分片 403 顶回来。
- **四层兜底**（都不针对具体站点）：
  1. **Referer 回退**（`RefererFallbackDataSource`）：先按带 Referer 试，只有 401/403 才换成不带 Referer 的源，**在同一次 `open()` 内**完成。拒绝按**主机**记，且记在 `Factory` 上、跨 `DataSource` 实例共享——HLS 一次播放要开几百次连接，每次都是新建实例，不共享就是每个分片先撞一次 403。非 401/403 不重试（404 换了也一样 404）。**不能改成一律不带 Referer**：那会弄坏另一批必须带 Referer 的站点，两种站点都存在，只能先试一种、被拒了再退。播放与离线下载共用这条数据源；下载侧原来是完全不带的，现在也接上（否则「必须带 Referer」的站点下不动）。
  2. **播放列表识别口径对齐**：`MediaSniffer` 收地址时认「串里出现过 m3u8」（不少站点的列表路径没有 `.m3u8` 后缀），播放器建源原来只认后缀。现在 `MediaUrls.isHls` 用同一把尺子，避免「嗅探到了却按直链建源」。
  3. **换源重试**（`PlayerActivity.retryWithOtherSource`）：容器猜错时 ExoPlayer 报的是解析类错误，这时把 HLS 与直链互换、从原进度重来一次。只换一次；只对解析类错误与 `INVALID_HTTP_CONTENT_TYPE` 换（编解码器不支持、无权限这类换了也白换，白等一轮还看不到真报错）。
  4. **失败提示带底层原因**：`errorCodeName` 之外补上最内层那句 message（HTTP 状态码、解封装失败位置），截断到 120 字，免得二进制上下文把错误码挤没。
- **站点本身拿不到的**：4K 档要客户端、720/480 要 VIP——这不是播放器能绕的，地址压根没发给网页端。归到「明确没做的」。

### 5.17 继续观看的数据（1.11）

- **目的**：主页那张卡片（见 5.1）要的东西——「最近看过的几集，按最近排序」。进度从 1.7 起就按地址记着，只是从来没露出来过。
- **存储形状换了**：1.10 及以前是「一个地址一个键」（`pos_<url.hashCode()>` → Long）。现在是一个**按时间倒序的 JSON 数组**（`resume_v2`），每条 `{url, title, referer, position, duration, at}`。
  - 为什么必须换：主页要按最近顺序列出来，而只存「地址 → 进度」的话，得把偏好文件里所有键捞出来才能拼出这个列表——键名是 URL 的哈希，反推不回地址。标题和来源页也得存：前者用来认出是哪一集，后者要交回播放器当 Referer（见 5.16）。
  - **老进度不丢**：`resumeMs()` 先查列表，列表里没有就回退去查 1.10 那个旧键。旧记录不会出现在「继续观看」里（它没有标题和时间），看一次就补上。
- **不记的规则没变**（1.7 定的）：看得太浅（不足 5 秒）或已经看到结尾（离结束不足 30 秒）都不记——否则用户重开时会「接着播」到第 3 秒或直接跳到结尾，比从头播还烦。时长还没读出来时不能按「看完了」处理，否则长视频看到一半就丢了进度。
- **上限 30 条**：列表会随着观看记录无限长下去，超出时丢最旧的。
- **读坏数据当空列表**：这个列表在主页首屏上，不能因为一条坏 JSON 崩掉；缺 `url` 的记录跳过，其余照常读出来。
- **刷新时机**：每次回到前台重读一遍（`LifecycleEventEffect(ON_RESUME)`）。进度是内置播放器在另一个界面写的，同一个进程、同一个偏好文件。

### 5.18 请求桌面版网站（1.11）

- **目的**：手机上打不开的网页，基本都只给桌面端排版。视口相关的两个开关（`useWideViewPort` / `loadWithOverviewMode`）一直是开着的，缺的就是一个 UA 开关。
- **入口两处，生效一条路**：主菜单新增「页面」组（`SettingRow`，右侧显示「已开启 / 已关闭」）+ 设置里「浏览」组的开关。两处改的是同一份设置（`BrowserStore.desktopMode`，默认关——绝大多数站点在手机版下更好用），真正换 UA 的动作统一由 `LaunchedEffect(desktopMode)` 触发，不会有一边忘了重载。
- **必须重新加载**：站点是拿 UA 决定发哪套页面的，已经在看的这一页还是按老 UA 发下来的那一套。只改 UA 不重载，用户点了开关却看不出任何变化。所以 `WebViewPool.applyDesktopMode` 会给每个标签换 UA，**并重载已经有地址的那些**（空白标签没什么可刷新的，不发这次请求）。
- **UA 没变就不重载**：每次回到前台都会走一遍这条路径，白重载等于页面莫名其妙自己刷新。
- **关掉时换回设备默认 UA**，不是写死一个手机 UA：WebView 版本一变，写死的那个就过期了。默认值在**第一次建 WebView 时**抓（那时还没被我们改过），拿不到就宁可不动——给一个错的 UA 比不改更糟。
- **池传的是取值 lambda 而不是 Boolean**：池的生命周期长于组合，传值的话新建的标签会读到池创建那一刻的旧设置（与 `blockTrackers` 同一处理）。
- **UA 用 Windows 上的近期 Chrome**：站点认的是「桌面」这个信号，不是具体版本号；但版本号太老会被一部分站点判成「不支持的浏览器」而直接拦掉。

## 8. 无障碍（Accessibility）

- 正文与次级文字对比 ≥ 4.5:1，大字号 ≥ 3:1（已在上表实测）。
- 所有可点目标 ≥ 48×48dp；相邻 ≥ 8dp。
- 图标按钮必须有可访问名称（如 `aria-label="关闭标签页"`），并暴露 `selected` / `expanded` 状态。
- 屏幕阅读器焦点顺序 = 视觉顺序；底部工具栏顺序：返回 → 前进 → 主页 → 标签 → 菜单。
- 支持系统字号放大至 200% 不破版；支持「移除动画」。
- 不以颜色为唯一指示（安全/警告同时有图标 + 文字）。
- 面板/抽屉打开时焦点被捕获，关闭后焦点回到触发按钮。
- 拖动/滑动类操作（边缘返回、标签排序）必须提供按钮等价物。

## 9. 实现注意事项（Jetpack Compose）

- 列表一律用 `LazyColumn` / `LazyVerticalGrid`，禁止 `Column + verticalScroll` 承载长列表。
- 每屏只保留**一个**滚动容器，避免嵌套滚动。
- `remember` 只存 UI 状态（滚动位置、动画）；业务状态放 ViewModel，列表用不可变集合（`PersistentList` / `ImmutableList`）。
- 主题用 `MaterialTheme` + 自定义 `CompositionLocal` 暴露语义 token，禁止在 Composable 内写死颜色。
- 地址栏 `TextField` 用 `KeyboardOptions(imeAction = Go)`，支持粘贴、密码管理器与自动填充。
- WebView 封装为独立 `BrowserView` Composable，生命周期与返回键由 `BackHandler` 统一接管。
- 边缘返回手势与 WebView 自身手势冲突需显式配置（`systemGestureExclusion`）。
