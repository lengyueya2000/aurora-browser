# 追剧模式（1.14）设计规格

> 版本：v1.0 · 2026-10-11
> 归属：主设计规格 `docs/superpowers/specs/2026-10-11-android-browser-design.md` §5.19
> 原型：`prototype/index.html` 屏幕 **15（播放器 · 选集面板）** 与 **16（片尾自动下一集）**
> 目标版本：1.14（versionCode 15）

---

## 1. 目的

一句话：**让「看完一集自动看下一集」这件事在浏览器里成立。**

现状是断的。选集列表在**网页的 DOM** 里，真实流地址在**网络层**（`MediaSniffer`），播放能力在**原生播放器**（`PlayerActivity`）。三者之间没有通路，所以一集播完，用户要走六步：退出全屏 → 回到网页 → 找到下一集 → 点开 → 等页面加载与嗅探 → 再进播放器。而用户真正想干的事只有一件：接着看。

这件事只能由浏览器做，这是它相对其他客户端的结构性优势：

- 别的播放器（VLC、MX Player）拿不到网页里的选集列表——它们没有页面。
- 网页播放器拿不到原生播放器的能力——它连自己的画面都被站点塞进 `blob:` 壳子里。
- 只有同时握着「页面 DOM + 网络层嗅探 + 原生播放」三样的客户端，才能把这条链路接起来。

## 2. 范围

### 2.1 本期（P0，1.14）

| # | 内容 |
|---|---|
| 1 | 页面侧提取选集列表（注入脚本抓候选，Kotlin 侧判定） |
| 2 | 播放器内选集面板（点标题行打开） |
| 3 | 点某一集 → 切集播放 |
| 4 | 播完自动下一集（倒计时，可取消） |
| 5 | 剧集状态标记（正在看 / 已看 / 未看） |
| 6 | 切集时让浏览器标签跟着换地址（退出全屏时人在对的页面） |

### 2.2 明确不做

写在这里免得装完才发现——每一条都有具体原因，不是「以后再说」：

- **整季批量离线**（P1）。每一集的真实流地址都得先跑一次嗅探才知道，一季 24 集就是 24 次静默加载。技术可行，但这是另一个体量的功能，本期的骨架先跑通。
- **精确片尾跳**。只能做到「播完（`onEnded`）才跳」，做不到「片尾曲一开始就跳」——后者需要知道片尾时长，那属于「用户教的片头片尾」，P1。
- **从主页「继续观看」进入时也能选集**（P1）。选集列表随播放会话走（Intent），从主页续播时没有页面上下文。P1 把它随进度一起存进 `PlaybackPreferences`。
- **跨站续播**（同一部剧换个站接着看）。这是独立功能，单独规格，不塞进这里。
- **跨域 iframe 里的选集**。注入脚本进不去跨域 iframe（同源 iframe 可以）。站点把选集放跨域 iframe 里的，本期抓不到。
- **自动识别「这一集是第几集」**。只用站点自己写的标签（`第 3 集` / `EP03` / 数字块），不做猜测。猜错的代价是跳错集，比不跳更糟。

## 3. 技术骨架

### 3.1 三条链路

```
① 提取     页面 DOM ──注入脚本──▶ 候选链接 ──Kotlin 纯函数──▶ EpisodeList
② 传递     BrowserScreen ──Intent（JSON）──▶ PlayerActivity
③ 切集     PlayerActivity ──隐藏 WebView 嗅探──▶ 新一集的流地址 ──▶ 播放
                              └──通知──▶ 浏览器标签换地址（可选，不阻塞播放）
```

### 3.2 为什么切集要由播放器自己开一个隐藏 WebView

这是本期最关键的一个决策，值得写清楚。

直觉方案是「让浏览器那个标签去加载下一集，嗅探到地址再回给播放器」。它在模拟器上大概能跑，但真机不可靠：**播放器盖在浏览器上时，浏览器那个 Activity 已经 stopped**，它的 WebView 窗口不可见，WebView 会throttle 定时器。而这些站点的流地址十有八九是**页面里的 JS 现算出来的**（4kvm 就是自己的 WASM 签时间戳，见主规格 5.16），JS 不跑就不会发那个请求，`shouldInterceptRequest` 自然什么也嗅不到。等用户退出全屏、浏览器 Activity 重新可见，页面才开始跑——那时候播放器早就在等一个永远不来的回调。

所以：**`PlayerActivity` 自己起一个隐藏的 WebView（1dp、不可见、不参与布局）专门用来嗅探下一集**。它跟着播放器的可见性走，JS 正常执行；`CookieManager` 是进程全局的，登录态自动带过去；UA 按当前「桌面版网站」设置显式设一遍（否则桌面版站点会给另一套 DOM）。

这也是唯一能覆盖「地址由站点 JS 现算」这类站点的做法——我们不去构造 URL，而是把真实页面跑一遍，让站点自己把地址算出来，我们在网络层接住它。

用完立刻销毁（一个 WebView 二三十 MB），同一时刻只存在一个。

### 3.3 「标签跟着走」是锦上添花，不是依赖

切集成功后再通知浏览器把该标签导航到新一集的页面地址。这样用户退出全屏时，看到的就是正在看的那一集，而不是上一集。

它**不参与播放链路**：通知失败、没有标签上下文（从主页续播进来）、标签已经被回收，都不影响播放。而且标签那一次 `loadUrl` 发生在不可见的 Activity 里，页面能不能渲染完不重要——用户回来时它自然会渲染。

## 4. 数据契约

### 4.1 页面 → 宿主：候选链接

注入脚本**只负责抓候选**，不做任何判定（判定逻辑放 Kotlin，见 5.1）。`evaluateJavascript` 返回数组：

```json
[
  { "href": "https://www.olevod.com/player/vod/1-82861-2.html", "text": "第 2 集", "inList": true },
  { "href": "/player/vod/1-82861-3.html",                        "text": "3",      "inList": true },
  { "href": "https://www.olevod.com/voddetail/1-82861.html",     "text": "详情",    "inList": false }
]
```

| 字段 | 含义 |
|---|---|
| `href` | 原样的 `href` 属性值，**不**在脚本里绝对化（Kotlin 侧统一处理，便于单测） |
| `text` | 链接文本，`trim()` 后截断到 24 字 |
| `inList` | 是否落在疑似选集容器内（脚本的容器启发式，见 5.2） |

上限 **400 条**候选，超出截断（防止把整页链接都拖出来）。

### 4.2 宿主 → 播放器：Intent

`PlayerActivity.intent(...)` 新增四个 extra，都是可选的（没有就是单集视频，一切照旧）：

| extra | 类型 | 说明 |
|---|---|---|
| `EPISODES` | String | 剧集 JSON：`{"series":"功夫女足","current":1,"episodes":[{"label":"第 1 集","url":"https://…"}, …]}`，上限 300 集 |
| `EPISODE_INDEX` | Int | 当前集下标（`-1` 表示当前页不在列表里） |
| `INCOGNITO` | Boolean | 来源是无痕标签：「已看」标记不落盘（见 7） |
| `DESKTOP` | Boolean | 当前是否「请求桌面版网站」。切集的嗅探窗口要用同一个 UA，否则桌面版站点给的是另一套 DOM |

**剧名不单独占一个 extra**：它已经在 `EPISODES` 的 JSON 里（`series` 字段），再传一份就是同一个值有两个来源，迟早漂移。

体积：一季 100 集 × 每条约 120 字节 ≈ 12 KB，远低于 Binder 的 1 MB 上限。300 集的上限是防呆，不是防 Binder。

已有的 `EXTRA_URL` / `EXTRA_TITLE` / `EXTRA_REFERER` / `EXTRA_START_MS` 不变——单集视频走的还是原来那条路。`EXTRA_TITLE` 传的是**页面标题**（基础名），播放器自己算出显示用的 `剧名 · 第 N 集`；切集之后这个基础名不变，标题跟着选集状态走。

### 4.3 播放器 → 浏览器：只是通知

```kotlin
/** 播放器切集后，通知浏览器把该标签挪到这一集。失败无所谓，播放不依赖它。 */
interface EpisodeTabSync { fun onEpisodeChanged(pageUrl: String) }

object EpisodeSession {
    @Volatile var tabSync: EpisodeTabSync = NoopEpisodeTabSync
}
```

- `NoopEpisodeTabSync` 什么都不做——没有宿主（单测、从主页续播进来）时静默，不崩。
- 具体实现由 `BrowserScreen` 在 `DisposableEffect` 里装上、离开时卸掉，与 `pool.onTitle` / `pool.onRenderGone` 同一处（见主规格 5.3）。
- **单向**：只有「告诉浏览器去哪一页」这一个方向。播放器不需要等浏览器回话——这正是 3.2 的收益。

## 5. 页面侧提取

### 5.1 脚本只抓候选，判定放 Kotlin

注入脚本里不写「什么算选集」的判断，只做两件事：按容器启发式收集 `a[href]`、标出哪些在疑似容器里。**是不是选集、怎么排序、当前是哪一集，全部在 Kotlin 侧的纯函数里判**。

这么切的原因有三条：判定规则是这个功能里最需要反复调的部分，放在 Kotlin 里能写单测、改一次不用重装页面逻辑；脚本越简单越不容易被站点的 CSP 或 DOM 重建搞坏；脚本的返回值是数据不是结论，宿主可以拒绝坏数据（跟 `MediaAction.isValid` 同一个思路）。

### 5.2 容器启发式（脚本侧）

按优先级找候选容器，命中就不再往下找：

1. `class` / `id` 里含 `episod` / `playlist` / `play-list` / `select` / `juji` / `集` 的元素，及其内部的 `a[href]`；
2. `<ul>` / `<ol>` 里含 ≥ 3 个 `li > a[href]`、且这些链接的路径前缀相同；
3. 兜底：页面上所有 `a[href]`，`inList` 全标 `false`（交给 Kotlin 的簇判定兜底，见 5.3）。

前两条命中的候选标 `inList: true`。脚本幂等（`window.__auroraEpisode` 守卫），可重复执行。

### 5.3 簇判定（Kotlin 纯函数）

`EpisodeList.parse(raw, pageUrl, pageTitle): EpisodeList?`。步骤：

1. **清洗**：只留 `http` / `https`；按 `pageUrl` 绝对化相对地址；按绝对化后的地址去重；截断到 300 条。
   注意**不丢当前页自己**：站点常把正在播的那一集也渲染成链接，留着它才能标出「正在看」、也才有它自己的标签可用。判簇靠的是「主键与当前页相同」，不靠「列表里有当前页」。
2. **算主键**：取 URL 路径最后一段，去掉扩展名，把**最后一段连续数字**换成 `#`。
   `1-82861-2.html` → `1-82861-#`；`play/ch4k8uf4p` → `ch4k8uf4p`（无数字，主键即自身）。
3. **分簇**：主键相同的归为一簇。要求同一簇 **≥ 3 条**（2 条太容易是「上一集/下一集」两个按钮），且**必须包含当前页**（`pageUrl` 的主键相同）。
4. **兜底**：主键法失败时，退化为「同 host + 同路径前缀 + 查询串里只有 `ep` / `episode` / `index` / `sid` / `id` 这类参数不同」的簇，同样要求 ≥ 3 条并包含当前页。
5. **两条都失败 → 返回 `null`**（当作单集视频）。宁可漏，不可错。
6. **排序**：优先按 URL 主键位上的数字；数字取不到时按文本里的数字（`第 3 集` → 3）；都取不到就保持文档顺序。
7. **定位当前集**：`pageUrl` 去掉查询串与尾斜杠后与某条相等 → 该条下标；找不到则 `currentIndex = -1`（面板照常列，只是没有「正在看」的高亮）。

阈值取严是有意的：把「相关推荐」误判成选集，后果是面板里冒出一堆不相关的集——不至于坏，但很难看，而且用户会以为功能是坏的。

### 5.4 剧名清洗

`seriesTitle(pageTitle, pageUrl)`：从 `<title>` 里依次去掉

- `第 N 集` / `第N集` / `EP\d+` / `第 N 季`；
- 常见的站名后缀（` - 欧乐影院`、`_在线观看`、`高清完整版`、`免费在线播放`）；
- 连续分隔符与首尾空白。

全被削掉时退回 host。清洗结果只用于显示（标题行、主页卡片），不参与匹配。

### 5.5 求值时机与重试

提取**按需触发**，不在每次 `onPageFinished` 都跑（没必要为不看的页面付这个代价）。脚本是纯读函数（不写 DOM、不加事件），所以 `evaluateJavascript` 直接求值就行，**没有「注入」这一步**——也不需要 `window.__xxx` 幂等守卫。

求值带**重试**：立即一次、800ms 一次、2500ms 一次（与缩略图那三拍同一个思路，见主规格 5.4），先拿到非空结果就停，最后一拍还没有才回 `null`。SPA 站点的选集常是异步渲染的，`onPageFinished` 那一刻可能还没有。

**但进播放器那一次只等第一拍。** 用户按下「全屏」的这一刻页面早就加载完了，选集要是在 DOM 里，这一拍就够；为了等 SPA 迟到的列表把开播拖慢 2.5 秒，对占绝大多数的单集视频是纯粹的伤害。所以：

| 触发点 | 时间表 | 为什么 |
|---|---|---|
| 进播放器前（`MediaAction.PLAY`） | `[0]` | 开播不能等。抓不到就当单集视频，按钮缺席好过按钮点了没反应 |
| 别的调用方（未来的「在网页里直接选集」等） | `[0, 800, 2500]` | 没有开播延迟的顾虑，可以多等一会儿 |

代码上就是 `WebViewPool.extractEpisodes(..., gaps = longArrayOf(0L))`。

**代价说清楚**：异步渲染选集、且用户在列表出来之前就按了全屏的页面，这一次拿不到选集——退出重进或刷新后就好了。这是刻意的取舍，不是漏洞。

## 6. 播放器侧

### 6.1 标题行：唯一的入口

标题行现在显示 `剧名 · 第 1 集`，**末尾带一个 `caret-down`（16dp）**表示可展开；整行可点（命中区 ≥ 48dp 高），点开选集面板。

- 入口放这里而不是加一个 chip：右下那排已经有 4 个（倍速 / 画质 / 适应 / 退出全屏），再塞一个在 412dp 宽度上会挤；而「第 1 集」这几个字本来就在标题里，点它换集是最自然的心智模型——跟视频 App 点剧名看选集一样。
- **没有选集时，标题行不带 caret、不可点**。按钮缺席比按钮点了没反应好，但这里更准确的说法是：它本来就不是按钮。
- 标题宽度上限仍是 60%（给右上角那排留位置），caret 含在这 60% 里；标题单行省略。
- 无障碍：语义为按钮，名称「选集，第 1 集，共 24 集」；没有选集时是纯文本。

### 6.2 选集面板

底部抽屉（复用 `AuroraBottomSheet`），三块：

1. **头部**：剧名（单行省略）+ 右侧 `共 24 集`。
2. **开关行**：「自动播放下一集」。与设置页 / 隐私页同一套做法——`SettingRow(toggleState = …, trailing = { Switch(onCheckedChange = null) })`：整行是点击目标、语义是开关（`toggleable(role = Role.Switch)`），`Switch` 只做展示，避免双重触发（见主规格 5.11 / 8）。默认**开**。持久化在 `PlaybackPreferences`。
3. **剧集网格**：每行 5 格（412dp 下 5×64dp 加 8dp 间距正好铺满），每格高 44dp、圆角 `--radius-sm`：

| 状态 | 表现 |
|---|---|
| 正在看 | 品牌色描边 + 品牌色文字（`--color-brand`） |
| 已看 | 文字 `--color-text-muted` + 右上角对勾 |
| 未看 | 底 `--color-surface-hover`、文字 `--color-text` |

格子里的文字是**集号**（「12」），不是完整标签——「第 12 集」在 64dp 的格子里放不下。集号取不到时用原标签截到 4 个字。

网格区**自己滚**（上限 460dp，与浏览器里的 `SheetContentMaxHeight` 取同一个值）：一季 100 集的话 20 行会把「自动播放下一集」那行挤出视野。最后一行不满时用空位撑住，5 列宽度才一致。

网格下面一行图例（正在看 / 未看 / ✓ 已看）——「已看」不只靠颜色，同时有对勾（见 8）。

点任意一格 → 关闭面板 → 走切集流程。当前集也可点（等于重播，从该集进度继续）。

**面板在控制层之外**：它是全屏遮罩 + 底部抽屉，不跟着控制层的自动隐藏一起淡出；面板开着时控制层也不自动隐藏（标题行是它的入口，收起来会让「关掉面板」没有落点）。

### 6.3 自动下一集

触发点是 `onEnded`（已有的回调）。分三种情况：

- **有下一集 + 开关开** → 画面中央出现倒计时卡片：`下一集 · 第 2 集` / `3 秒后自动播放` / 两个按钮 `立即播放`、`取消`。3 秒后走切集流程。
- **开关关** → 停在结尾、把控制层显示出来（与 1.13 行为一致，用户自己决定）。
- **已经是最后一集** → 停在结尾，卡片改成 `已经是最后一集`，1.5 秒后自动消失。给这一句是因为用户此时会期待「自动播」却没发生，得有个说法。

倒计时期间：点「取消」或按返回键取消；点卡片以外的任何位置也取消（同时保持控制层可见）。**点画面不进入下一集**——误触进下一集比多按一次取消烦人得多。取消后停在结尾，不自动重播。

### 6.4 进度归属（最容易写错的地方）

**切集后一律按新集的地址重新查进度，绝不继承当前集的 `positionMs`。**

这条看着显然，但写起来很容易顺手把当前播放位置带过去（`EXTRA_START_MS` 就在手边）。带过去的后果是：第 1 集看到 40:00 播完，切到第 2 集直接从 40:00 开始——如果第 2 集只有 42 分钟，用户看到的是「下一集刚点开就结束了」。

规则统一成一句：**切集 = 用新集的地址重建一次媒体源**，除了「当前集下标」更新，其余（进度、清晰度选择、倍速）都按新地址重新解析。所以：

- 自动下一集 → 新集进度通常是 0（它没被看过），从头播。✔
- 手动点第 5 集 → 如果第 5 集看过一半，接着看。✔（这是好事，不是 bug）
- 手动切走时**当前这一集的位置会先存下来**（`rememberPosition()`），用户切回来还接着看。已经播完的集不会被存进去——`PlaybackPreferences.remember` 会把「离结尾不足 30 秒」的一律丢掉（见主规格 5.17），所以自动下一集这条路上不会把看完的集又写回列表。

顺带：`onEnded` 已经把这一集的进度 `forget()` 掉了（见主规格 5.17），所以「继续观看」列表里不会堆一串看完的集——正好是我们要的。

### 6.5 切集的等待与失败

点选某一集后：

1. 面板关闭，画面中央转圈 + 一行 `正在获取第 2 集…`（与缓冲转圈同一套视觉，但多一句话——「点了第 5 集却什么都没发生」和「正在取第 5 集」是两种完全不同的体验）。当前这一集继续播，不暂停。
2. 隐藏 WebView 加载该集页面，等 `onPageFinished` + 嗅探到可播地址。**超时 12 秒**（时间表 0 / 0.8 / 2 / 4 / 7 秒各查一次，最后一拍兜底）。
3. 成功 → 重建媒体源，Referer 用**新一集的页面地址**（不是上一集的——Referer 是站点校验热链的凭据，见主规格 5.16），标题更新为 `剧名 · 第 2 集`，并通知标签跟着走。
4. 失败或超时 → 提示 `没能取到第 2 集（等这一集的地址等超时了），可以回到网页手动点一下这一集`，**留在当前集**。不退出播放器、不黑屏，当前这一集照常在放。提示里既说清「怎么办」，也留着底层原因——用户报障时那句原因比「失败了」有用得多。
5. 切集期间用户按返回 → 退出播放器；隐藏 WebView 由 `onDestroy` 销毁。

**迟到回调要作废**：连续两次切集（用户手快连点两集）时，第一次的嗅探回调必须被丢弃，否则会把用户带回第一集。做法与缩略图那套一样——每次切集递增一个 token，回调里比对 token 不等就丢弃（见主规格 5.4 的 `captureTokens`）。这个坑缩略图那边踩过一次，这里不能踩第二次。

## 7. 状态与边界

| 状态 | 表现 |
|---|---|
| 页面没有选集 | 标题行不带 caret、不可点；面板打不开；播完停在结尾（与 1.13 一致） |
| 只有 1 集 | 同上（阈值是 ≥ 3 条才算剧集，见 5.3） |
| 选集 URL 跨域 | 该条丢弃；全跨域则视为没有选集 |
| 当前页不在列表里 | 面板照常列，只是没有「正在看」高亮（`currentIndex = -1`） |
| 从主页「继续观看」进入 | 没有选集（P0 限制），标题行无 caret；播完停在结尾 |
| 切集超时 | 提示 + 留在当前集，可重试 |
| 无痕标签 | 选集可用（不落盘）；「已看」标记不写——与「无痕不记历史」同一个口径 |
| 进程被回收后重建播放器 | 选集来自 Intent，能继续切集；隐藏 WebView 现建 |
| 剧集页在跨域 iframe 里 | 抓不到 → 没有选集 |
| 标签被渲染进程崩溃回收 | 「标签跟着走」静默跳过，播放不受影响 |

## 8. 无障碍

- 标题行（有选集时）暴露为按钮，名称「选集，第 1 集，共 24 集」。
- 网格每格命中区 ≥ 48dp，名称「第 2 集」，状态如实暴露：`selected`（正在看）或可访问描述「已看过 / 未看过」。不以颜色为唯一指示——「已看」同时有对勾图标。
- 倒计时卡片用 `liveRegion = Polite` 播报一次「3 秒后播放下一集」，不抢焦点、不打断用户正在听的读屏内容；两个按钮都是独立的可聚焦目标。
- 面板打开时焦点被捕获、关闭后回到标题行（与既有抽屉一致）。

## 9. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 站点结构千差万别，**一定有一批站抓不到** | 优雅退化：抓不到就是单集视频，一切照旧。绝不因为抓不到就少个按钮、弹个错。这是「宁可没有，也不能错」 |
| 主键法可能把「相关推荐」误判成选集 | 阈值取严（同簇 ≥ 3 条、必须包含当前页、优先要求 `inList`）。误判的代价是面板难看，不是坏功能 |
| 静默加载多耗一个页面的流量（几十到几百 KB） | 只在用户主动切集 / 自动下一集时发生；接受这点代价——它换来的是「地址由站点 JS 现算」也能切集 |
| 隐藏 WebView 的内存（一个二三十 MB） | 同一时刻只存在一个，用完立刻销毁 |
| SPA 站点切集不换 URL，「标签跟着走」可能让页面重载 | 可接受：它只为「退出全屏时人在对的页面」，重载不影响已经切好的播放 |
| 站点可能对同一页面的重复加载做统计/风控 | 加载时不自动播放（`setMediaPlaybackRequiresUserGesture(true)`），静音 |
| 12 秒超时对慢站可能不够 | 超时给可读提示而不是静默失败，用户可再点一次 |

## 10. 测试计划

本期新增 **57 例**，全绿（总数 450 → 507）。实际落到的四个类：

**`EpisodeCodecTest`（22 例，Robolectric）** —— 判定是纯函数，但读写 JSON 用的是 `org.json`，而它只在 Robolectric 下可用，所以整个类跑在 Robolectric 里（不起 Activity、不碰 WebView）。

- 主键：`1-82861-2.html` → `1-82861-#`；`1-82861.html`（详情页）→ `1-#`（**不**拿 82861 当集号）；末段无数字 → 主键即自身。
- 集号：URL 末段的尾数字优先，其次标签里的第一个数字。
- 分簇：同簇 ≥ 3 条且主键与当前页相同才算剧集；2 条 → `null`；「相关推荐」落在另一簇、被忽略；容器信号（`inList`）优先于数量。
- 查询串兜底：`?ep=` 这类成立；`?sort=a|b|c` **拒绝**（那不是集号，是筛选条件）。
- 相对地址按 `pageUrl` 绝对化；非 http(s) 丢弃；重复丢弃。
- 当前集定位：带尾斜杠、带片段都命中；页面不是链接时 `currentIndex = -1`。
- 剧名清洗：`功夫女足 第 1 集 - 欧乐影院` → `功夫女足`；全被削掉时退回 host。
- 坏 JSON / `null` / 空数组 → `null`；超过 300 条截断；候选超过 400 条截断。
- JSON 往返（`toJson` → `fromJson`）。

**`EpisodePlaybackTest`（12 例）** —— 播放器里的选集状态。

- 单集视频没有选集、没有下一集、标题原样回退。
- 下一集是紧随的那一集；最后一集没有下一集；下标越界没有下一集。
- 当前集不在列表里（`index = -1`）时下一集是列表第一条——站点把正在播的那集渲染成 `<span>` 时就是这种情况。
- 标题：`剧名 · 第 N 集`（集号从 URL 取，比页面上的「12」清楚）；没有集号的标签原样用；当前集不在列表里时回退到原标题。
- 开关是数据的一部分，`withAutoNext` 不改原对象。

**`EpisodeSnifferTest`（12 例，Robolectric）** —— 这个类最容易错的全是时序。

- 页面地址被真的加载；窗口挂进宿主且 `alpha = 0`。
- 页面加载完 + 嗅到流 → 交付；**页面没加载完就先拿到地址 → 不交付**（站点常在正式流之前先拉一个预览片）。
- 不是媒体的请求被忽略，紧接着的真流照常交付。
- 时间表最后一拍是兜底的：`onPageFinished` 迟迟不来时也能交付。
- 什么都嗅不到 → 走到超时才失败。
- `cancel()` / `destroy()` 之后不再回调，且 WebView 被销毁、从宿主摘掉。
- **连续两次切集，第一次的迟到回调被丢弃**（token 作废）——对应 6.5 的回归测试。
- 交付之后窗口自己释放。
- UA：给了就设，没给不动。
- 宿主传 `null` 也不崩。

**`PlaybackPreferencesTest`（新增 11 例）** —— 自动下一集与「已看」。

- `autoNext()` 默认开、往返一致。
- 按剧记已看、跨剧不污染、重复标记是空操作、读回还是集号。
- `forgetWatched` 只清一部剧。
- 空键 / 负集号忽略；列表上限；坏 JSON 当空；少了 `key` 的记录跳过。
- `seriesKey` 带 host（两个站的同名剧不互相污染），且同一部剧的各集键一致。

**没进 CI 的两块，说清楚：**

1. **注入脚本的选择器集合**：Robolectric 跑不了真实 JS。验证方式是拿一段 DOM 桩把脚本跑一遍，人工核对候选 JSON 的形状与去重 / 上限行为——脚本负责抓、Kotlin 负责判，只有「抓」这一半需要人工看。本期核过的场景：关键词容器命中、`ul/ol` 里 ≥3 个 `li > a` 命中、无容器时兜底标 `inList:false`、`#` / `javascript:` / `mailto:` / `tel:` / `data:` / 空 `href` 全部丢弃、同 `href|text` 去重、600 条截到 400 条、空页面回 `[]`。
2. **播放器侧的界面流程**（标题行 caret、选集面板、倒计时卡片、切集后的进度归属）：`PlayerScreen` 是挂在 `PlayerActivity` 上、由 ExoPlayer 驱动的私有 Composable，单测里起不了。这几条只能真机实测——**这一轮真机实测未跑**。

## 12. 与既有功能的关系

| 功能 | 关系 |
