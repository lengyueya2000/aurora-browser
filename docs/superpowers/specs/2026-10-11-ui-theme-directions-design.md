# 极光浏览器 · 视觉方向规范（四套方案）

- **日期**：2026-10-11
- **文档版本**：v1.0
- **配套原型**：`prototype/themes.html`（浏览器直接打开，无需构建）
- **上一版设计原型**：`prototype/index.html`（1.15 现行界面，本方案的对照基线）
- **状态**：待选型。选完再进入代码落地，本文档不含实现步骤。

---

## 1. 这次要解决什么

现有界面是 1.15 的「现代简约 · 深色优先」——石板灰底 + 天蓝品牌色。它能用，但整套配色从第一版沿用至今没有重审过。这次给出**四套并行的视觉方向**供选型，覆盖**全部 16 屏**。

三个范围决定由你拍板，本文档按此执行：

| 决定项 | 选择 | 含义 |
|---|---|---|
| 覆盖范围 | **全部 16 屏** | 含设置、书签历史、无痕、阅读模式、选集面板、片尾卡等 |
| 差异层级 | **仅视觉层** | 信息架构、布局、交互、动效一律不动 |
| 明暗 | **不限** | 允许出现浅色优先的方案 |

---

## 2. 方法：一份标记 + 四套主题层

「仅视觉层」这个约束有一个直接的好处：**四套方案可以共用同一份 16 屏 HTML 标记**。差别只落在 CSS 自定义属性（token）上。

这不是一句自我声明，而是可以在文件里验证的事实：

- `prototype/themes.html` 里 `.board` 之内的 16 屏标记，是从 `prototype/index.html` **逐字抽出**的（构建脚本 `re.findall` 抽 `<main class="board">` 内容），没有一处为某个方案单独改过；
- 每套方案是 `[data-theme="a"|"b"|"c"|"d"]` 上的一层 token 覆盖，84–85 个变量；
- 选择器刻意写成 `[data-theme=...]` 而不是 `body[data-theme=...]`。自定义属性是**继承**的，所以挂在 `body` 上就是整站换肤，挂在某个 `div` 上就是**局部**换肤——「并排对比」正是靠这一点，把同一屏在四个主题里各渲染一份，同一屏并排放在一起。**如果四列有任何一处结构不同，并排对比会立刻暴露。**

顺带说明一处不得不做的改动：基础样式里原本有约 60 个写死的色值（设备边框、板底渐变、假网页底色、代码块配色、播放器遮罩等）。它们被**收编成新 token**，默认值等于现有深色方案，因此不带 `data-theme` 时渲染结果与原版一致。这是「换皮」能做到彻底的前提——否则换到浅色方案时，那些写死的深色值会留下来。

## 3. 四套方案

四套在三个维度上拉开距离：**明暗**（A 浅色 / B·C·D 深色）、**材质**（玻璃辉光 / 扁平描边 / 纸感发丝线）、**色相**（松绿 / 霓虹青紫 / 琥珀 / 青碧）。

### 3.1 方案 A ·「晨雾」— 浅色纸感 · 松绿

暖白纸底（`#FBF9F6`），发丝级分隔线（`rgba(28,27,25,.09)`），**几乎不用阴影**，层次靠字号与留白拉开。品牌色是偏冷的深松绿 `#0F5C4A`。

- **材质签名**：扁平 + 描边。快捷入口是「白底 + 1px 描边」而不是填充块；卡片一律 `box-shadow:none`；设备边框收窄到 7px。
- **圆角**：5 / 8 / 12 / 16 / 22（四套里最小）。
- **玻璃**：`blur 12px`，且玻璃面板用 80% 白而非半透明深色。
- **最适合**：白天与户外、长时间阅读、把浏览器当工具用的人。
- **代价**：深色场景下没有氛围感；观影时整机偏亮，夜里刺眼。**这是四套里唯一需要额外处理「画面上文字」的方案**（见 §4.2）。

### 3.2 方案 B ·「极夜」— 深色玻璃 · 霓虹青紫

在现有深色基础上再压暗一档（底 `#080B14`），品牌色换成电光青 `#38E1FF`，配一层紫 `#7C5CFF` 作次要辉光。

- **材质签名**：玻璃 + 辉光。工具栏带 22px 模糊和外发光；快捷入口是「青紫渐变 + 1px 青边 + 外发光」；选中的标签卡加 26px 品牌辉光；主按钮带投影辉光。
- **圆角**：8 / 12 / 18 / 24 / 34（四套里最大）。
- **最适合**：观影、媒体消费、想要「现代/有科技感」的观感。
- **代价**：最「重」，浅色环境反光下对比度吃紧；辉光多了在低端屏上可能有色带。

### 3.3 方案 C ·「墨玉」— 深色仪表盘 · 琥珀

中性炭黑（底 `#14161A`）+ 单一琥珀强调色 `#F0A322`。**完全不用辉光**，改用清晰可见的 1px 描边（`#3D434B`）和小圆角。

- **材质签名**：仪器面板。快捷入口是「填充块 + 1px 描边 + 无阴影」；分区标题字距拉到 `.16em`；所有数字（下载体积、计数、时长）启用 `tabular-nums` 等宽对齐。
- **圆角**：4 / 6 / 10 / 14 / 18（四套里最方正）。
- **最适合**：信息密度与「工具感」优先，下载管理/标签管理这类列表重的界面。
- **代价**：比 B 冷、比 A 暗，氛围感最弱；琥珀在深底上偏暖，长时间看容易显脏。

### 3.4 方案 D ·「青碧」— 深海青绿 · 单色相

底色本身就带青绿（底 `#0A1A18`，不是黑底配青绿点缀），品牌色青碧 `#2DD4BF`，**整套只用一个色相**。

- **材质签名**：单色辉光 + 薄玻璃。只有一层青绿辉光（不像 B 的青+紫双层）；快捷入口是「青绿渐变 + 青边 + 无阴影」；圆角居中。
- **圆角**：7 / 10 / 14 / 20 / 26（四套里居中）。
- **最适合**：想要深色但不要 B 那么「亮/吵」，希望品牌色统一克制的人。
- **代价**：与 B 同为深色系，如果最终只想要一套深色，B 和 D 需要二选一。

## 4. Token 架构

### 4.1 新增 token（基础层收编的写死值）

| 组 | token | 覆盖的原写死值 |
|---|---|---|
| 板底 | `--board-bg` `--board-layers` `--board-layers-size` | `body` 的 `#070b14` + 四层渐变 |
| 品牌柔色 | `--brand-soft` `--brand-soft-strong` | `rgba(56,189,248,.07)` / `.10`（页眉徽标、帧号、选中建议行） |
| 设备 | `--device-bezel` `--device-ring` `--device-shadow` | `#161b28` 边框与三层阴影 |
| 中性 | `--neutral-soft` `--neutral-soft-border` | 无痕页大圆、键盘键影 |
| 语义面板 | `--success-panel` `--success-panel-border` `--success-soft` `--warning-soft` `--success-soft-2` | 拦截计数卡、站点身份徽标 |
| 工具栏 | `--toolbar-accent-border` `--toolbar-inc-bg` | 无痕工具栏的青色描边 |
| 假网页 | `--page-bg` `--page-hero` `--page-hero-glow` `--code-bg` `--code-text` `--code-k/s/c` `--img-grad` `--img-glow-1/2` | 演示页底色、代码块语法色、配图渐变 |
| 缩略图 | `--thumb-bg` `--thumb-none` `--thumb-inc` `--thumb-close-bg` `--shot-bg` `--shot-line` `--shot-hero` `--shot-bg-2` `--shot-line-2` | 标签卡预览、列表小缩略图 |
| 播放器 | `--video-bg` `--video-stage` `--video-play-bg` `--video-play-fg` `--video-tb-bg` `--video-scrim` `--video-dl-bg` `--track-bg` `--pill-bg/fg/border` `--chip-bg` `--chip-on-bg` `--hint-bg` `--card-solid` | 画面底、中央播放键、±10 秒圆钮、进度轨、各类浮层药丸 |
| 其他 | `--panel-sheen` `--swatch-border` `--gesture-bar` `--bg-incognito` `--key-shadow` `--glass-blur` | 卡片渐隐、色卡描边、手势条、键盘键影、玻璃模糊半径 |

圆角、阴影、字距不新增 token——直接覆写现有的 `--radius-*` / `--shadow-*`，这正是四套方案「手感」差异的主要来源之一。

### 4.2 主题无关的 token：`--on-video`

**这是做浅色方案时暴露出来的一个真问题。** 播放器控制层里有一批文字是**直接压在视频画面上**的（剧集标题、`12:34 / 1:02:05` 时长、±10 秒圆钮）。它们原本走 `--color-text` / `--color-text-secondary`，而视频底在任何主题下都是深的。

浅色方案 A 把这两个 token 改成深色之后，这些文字**在深色画面上直接看不见了**——第一版渲染出来时标题和时长几乎是隐形的。

修法是新增三个**故意不随主题变**的 token：

```
--on-video:      #f8fafc          /* 压在画面上的文字，永远是浅色 */
--on-video-dim:  #cbd5e1
--on-video-chip: rgba(248,250,252,.14)
```

它们只在 `.pl-title` / `.pl-seek` / `.pl-tb` 三条规则里用。**规律**：有自己浅色底的浮层（`.pl-chip` 底部药丸、`.pl-dl` 下载状态卡、`.pl-hint`）走主题 token，因为它们的底色会跟着主题变；没有底的、直接浮在画面上的，走 `--on-video`。

> 这条规律以后加新控件时要遵守，否则会再犯一次。

## 5. 对比度实测

按 WCAG 相对亮度公式实算（脚本从 `prototype/themes.html` 的主题块里读实际 token 值，不是手抄）：

| 配对 | A 晨雾 | B 极夜 | C 墨玉 | D 青碧 | 现行深色（基线） |
|---|---|---|---|---|---|
| 正文 / 底 | 16.56 | 18.16 | 16.19 | 16.79 | 17.06 |
| 次级 / 底 | 10.62 | 12.91 | 11.65 | 13.15 | — |
| 弱化 / 底 | 5.51 | 7.45 | 7.04 | 8.00 | — |
| 正文 / 卡片 | 17.40 | 15.97 | 13.59 | 12.89 | — |
| 弱化 / 卡片 | 5.79 | 6.55 | 5.90 | 6.14 | — |
| 品牌 / 底 | 7.54 | 12.53 | 8.60 | 9.61 | 8.33 |
| 品牌上文字 | 7.92 | 12.09 | 8.71 | 9.09 | — |
| **禁用 / 底** | **3.21** | **4.37** | **4.05** | 4.81 | **3.75** |

结论：**所有承载信息的配对在四套方案里都 ≥ 5.5:1**，远高于 4.5:1 的门槛。

唯一低于门槛的是「禁用态文字」，四套里 A/B/C 都不足 4.5:1——但**现行已发布的深色方案是 3.75**，同样不足，且 WCAG 明确豁免禁用控件。也就是说这一点没有退步，但也没有改进；如果要求禁用态也达标，需要在选型后单独调 `--color-text-disabled`（A 的 3.21 最需要）。

## 6. 四套方案都不改的东西

明确列出，避免选型时产生「换这套是不是要重做 XX」的误解：

- **16 屏的标记与布局**：一模一样，逐字复用。
- **图标**：同一套内联 Phosphor Regular 路径，只换尺寸与颜色容器，不换图形。想换描边/填充风格是**另一个议题**（要重出 60 个图标路径），本轮不含。
- **交互与动效**：手势、按压反馈、面板开合、时长与缓动曲线都不动。按压态仍然只改颜色/透明度，不改布局尺寸。
- **触摸目标**：仍 ≥ 48dp。
- **字体族**：仍是 Inter + JetBrains Mono。C 额外启用了等宽数字对齐，A 微调了分区标题字距，仅此而已。
- **能力与文案**：不改任何功能、不删任何入口。设置页那行「主题 · 深色」当时是演示文案（浅色方案下也照抄），落地时已换成真的三档选择器，见 §9。

## 7. 已知边界与没做的事

- **深色方案 B 与 D 同属深色系**，如果最终只保留一套深色，需要在两者间二选一。这是设计上的取舍，不是遗漏。
- **C 的等宽数字**只对下载体积、计数、时长等几处生效；如果选 C，建议再走一遍全部数字场景，确认没有漏。
- **浅色方案 A 的播放器**依赖 §4.2 的 `--on-video` 才成立。若后续新增压在画面上的控件，必须沿用该 token。
- **未做真机验证**：本文档的对比度是公式实算，视觉结论来自 Chrome 渲染；OLED 屏上的实际观感（尤其 B 的辉光、C 的琥珀）需要在真机上再看一次。
- **几何未动**：四套方案各自定义了圆角刻度（A 是 5/8/12/16/22），而应用侧 `AuroraRadius` 是一个被 42 处引用的普通 object，改成随主题走要动全部调用点。1.16 只落了**色彩层**，圆角仍是 6/10/14/20/28。
- **B / C / D 未落地**：1.16 只实现 A。

## 7.5 落地记录（1.16）

用户选定 **A「晨雾」**。落地方式与 §9 的预判一致，逐条对照：

| 项 | 落点 |
|---|---|
| 浅色令牌 | `ui/theme/Tokens.kt` 的 `LightAuroraColors`（深色那套改名注释为 `DarkAuroraColors`，值一字未改） |
| 主题选择 | `domain/ThemeMode.kt`：浅色 / 深色 / 跟随系统，持久化在 `PrefsBrowserStore.KEY_THEME` |
| 默认值 | **浅色**。做成「跟随系统」的话，深色手机上装完看到的还是旧界面——用户选了新设计却要看设置页才知道自己拿到什么 |
| 播放器控制层 | `ui/theme/Tokens.kt` 的 `OnVideoColors`（= `DarkAuroraColors`），播放器里直接压在画面上的控件全部改读它 |
| 系统栏图标 | `MainActivity` 里按解析出的深浅色重复调用 `enableEdgeToEdge`，浅色令牌配深色图标 |
| 设置页 | 「外观」组从一行假的「深色模式 / 已开启」换成真的三档分段控件 |

与原型的两处刻意差异：

1. **`warning` 从 `#A9691A` 压到 `#A05F14`**：原型那版在纸白底上是 4.45:1，差 0.05 没过 AA。
2. **播放器遮罩用深色令牌的 72%，不用原型的 42%**：遮罩属于固定深色那一层，见 §4.2；沿用深色令牌意味着深色主题下的播放器外观与 1.15 完全一致。

浅色令牌暴露了三处「深色下靠亮度差、浅色下两边都是纯白」的塌陷，一并修了（都往原型靠）：

| 位置 | 症状 | 处理 |
|---|---|---|
| `SegmentedControl` | 选中段（`surface`）与轨道（`bgElevated`）都是纯白，看不出选了哪个 | 选中段加一圈 `border` 描边——原型那边靠 shadow 拉开，发丝线是平面设计的等价物 |
| `DownloadsScreen` 进度条 | 轨道（`bgElevated`）与卡片（`surface`）同为纯白，只剩填充那一截 | 轨道改用 `surfaceHover`（原型 `.bar` 用的也是这一档） |
| `ActionGridTile` | 底色与菜单面板同为 `bgElevated`，**深浅两套都没有底**（深色下也是） | 改 `surface` + `divider` 发丝线，与原型 `.act` 一致 |

验证：564 个单元测试全绿（含新增的浅色令牌值、WCAG 对比度、`ThemeMode` 行为、播放器控制层亮度共 10 条）；模拟器实测截图覆盖主页 / 菜单 / 设置（含三档切换与深色回归）/ 下载中与已完成 / 明亮视频上的播放器控制层。

## 8. 怎么评审

打开 `prototype/themes.html`（纯静态，无需构建）：

| 操作 | 效果 |
|---|---|
| 顶部三个/四个按钮，或按 `1` `2` `3` `4` | 整板瞬时切到对应方案 |
| 「并排对比」按钮 | 隐藏 16 屏板，改成**同一屏 × 四套方案**并排；可切 01 主页 / 09 下载管理 / 14 播放器控制层 |
| 深链 `#theme=b` | 直接进某一套 |
| 深链 `#cmp=8` | 直接进并排对比的某一屏 |
| 深链 `#frame=8` | 滚动到第 9 屏 |

深链是为了评审时能直接把「这一屏、这一套」发给别人，不用口头描述怎么点。

**建议的评审顺序**：先看「并排对比」的 01 主页定基调 → 再看 09 下载管理（列表最密，最能看出配色是否耐看）→ 最后看 14 播放器控制层（浅色方案的风险点集中在这里）。

## 9. 选完之后

选定一套（或「A 的浅色 + 某一套深色」这样的组合）之后，落地的改动面是：

1. 把该方案的 token 值搬进 Compose 的主题定义（`ColorScheme` + 自定义 token 的 `CompositionLocal`）；
2. `--on-video` 这类主题无关 token 单独成组，不参与主题切换；
3. 现有布局代码一行不动，单元测试不受影响。

**这三条的实际执行结果见 §7.5**——A 已在 1.16 落地，`AuroraTheme` 多了一个 `dark` 参数，`OnVideoColors` 独立成组，布局代码只动了 §7.5 表里那三处「深色下靠亮度差、浅色下塌陷」的地方。

「跟随系统深浅色」也做了：A 是浅色档、1.15 那套深色是深色档，设置页三档可选。所以 A 的定位最终是「默认的浅色模式」而不是「与深色并列的独立方案」——这是选型时留下、落地时一并解决的那个问题。
