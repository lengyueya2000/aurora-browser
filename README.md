# Aurora Browser（极光浏览器）

一款「全能功能型」安卓浏览器：在单手可及的界面上，把标签管理、拦截、阅读、下载、书签这些能力收进一个克制的深色界面里。

- **技术栈**：Kotlin + Jetpack Compose（Material 3）+ Android WebView
- **平台**：Android 8.0+（API 26+），targetSdk 35
- **视觉**：现代简约 · 深色优先（Dark Mode / OLED）

## 明确没做的

这些不是「以后再说」，而是当前版本确实没有的能力，写在这里免得装完才发现：

- **扩展**：Android WebView 没有扩展 API，`.crx`/`manifest.json` 那套只存在于桌面 Chromium。这不是排期问题，是平台不支持，所以菜单里没有扩展入口。
- **Chromecast 原生投屏**：没有接入 Google Cast SDK。它要求注册 Cast app id 并依赖 Google Play 服务，在没有 GMS 的设备上直接不可用，还会把闭源依赖引进来。也试过 `androidx.mediarouter` 的设备选择器，但它的 `MediaRouteChooserDialog` 继承 `AppCompatDialog`，要整个应用套上 AppCompat 主题——对一个纯 Compose 应用来说是为一颗按钮换掉主题体系，不划算，于是改成零依赖实现：屏幕镜像交给系统的投屏页，视频交给能播 `video` 通配 MIME 的应用（各类投屏播放器都在此列）。
- **逐站权限授权**：相机 / 麦克风 / 定位当前一律拒绝，没有「本站允许」的授权弹窗。唯一的例外是 DRM 的 protected media id——全屏播放加密流要用，且不是用户可见权限。
- **标签持久化**：进程被系统回收后标签页不会恢复，重启是全新一个标签页。
- **HLS 不能存成一个 mp4 文件**：这类站点（欧乐影院、各类影视站）只给 `.m3u8` 分片清单，没有直链 mp4。所以「下载」给的是应用内离线缓存——在下载页能看到、能打开、能离线播，但不会在文件管理器里出现一个 mp4。想要单文件得自己写 HLS 下载器再把分片拼起来，这一版没做。
- **同步、账号、查找页内文字、桌面模式、翻译、拦截规则在线更新**：都没有。
- **广告和正片拼在同一条流里的拦不住**：有些站点在服务端就把前贴片拼进了 m3u8，前几个分片是广告、后面才是正片——客户端看到的是一条连续的流，只有解出分片内容才分得出来。域名拦截和元素清理都够不着这一层。
- **需要登录 / 会员 / 客户端专用接口的清晰度拿不到**：4kvm.net 这类站点的播放地址是它自己的 WASM 现算出来的，`4K` 档直接回「仅支持客户端播放，Web端不支持」，`720/480` 档要 VIP。这不是播放器的问题，站点根本没把地址给网页端，浏览器拿不到就无从播起。
- **明文 HTTP 是放行的**：这是个浏览器，打不开 `http://` 站点等于不能用；地址栏的「不安全」标识负责提醒。

### 这一轮（1.9）：把「有些视频播不了」从逐个修变成一层兜底

起因是你报的 `https://4kvm.net/play/ch4k8uf4p` 播不了。查下来根因不在播放器，也不在那个站点的播放器实现，而在**我们比浏览器多做了一件事**。

**这个站的视频是怎么发的。** 页面里是 ArtPlayer + hls.js，播放地址由站点自己的 WASM 现算（`build_play_url` 签一个时间戳，再带上页面里那个 `userlink` 当访问令牌）。拿到 1080P 那条免费档的播放列表后发现三件反常的事：

- 分片地址指向 `file.icve.com.cn`（阿里云 Tengine），不是站点自己的域名；
- 分片后缀是 `.png`、`Content-Type` 是 `image/png`，但文件其实是「**61 字节的 1×1 PNG 头 + 一整段 MPEG-TS**」（H.264 + AAC，ffmpeg 封装的）。这是伪装，不是格式不支持——反编译确认 `TsExtractor.sniff` 会在前 940 字节里按 188 字节间隔找 5 个同步字节，找到后 `skipFully(offset)` 跳过那个 PNG 头，所以容器这一层本来就是通的；
- 那个 CDN 有 **Referer ACL**：`Referer: https://4kvm.net/…` → `403 denied by Referer ACL`，**不带 Referer → 200**。站点自己在页面里写了 `<meta name="referrer" content="no-referrer">`（盖掉响应头里的 `strict-origin-when-cross-origin`），让浏览器不发 Referer，从而绕过这个热链保护。

**我们为什么会踩中。** 1.5 起内置播放器会给每个请求带上页面地址当 Referer（当时是为了修另一些「必须带 Referer 才给数据」的站点）。于是网页里 hls.js 播得好好的，点进我们的播放器每个分片都被 403 顶回来——用户看到的就是「这种格式的视频播放失败」。

**修法不是给这个站开后门，而是四层通用兜底**（`RefererFallbackDataSource`、`MediaUrls`、`PlayerActivity`）：

- **Referer 被拒就退到不带 Referer 重开**。先按带 Referer 试，只有被 401/403 明确拒绝才换成不带 Referer 的源，在**同一次 `open()` 内**完成，用户不必自己重试。拒绝按**主机**记，而且记在工厂上、跨 DataSource 实例共享——HLS 一次播放要开几百次连接，不共享的话每个分片都要先撞一次 403，等于请求量翻倍。其它状态码（404 之类）不重试，免得白等一轮还看不到真正的报错。下载用的数据源也接上了同一条路（原来它根本不带 Referer，反过来在「必须带 Referer」的站点上下不动）。
- **播放列表的识别口径对齐**。`MediaSniffer` 收地址时认「串里出现过 m3u8」（因为不少站点的列表路径没有 `.m3u8` 后缀），但播放器建源时只认后缀——嗅探认了、建源不认，就会出现「地址拿到了却一报容器不支持」。现在两处用同一把尺子。
- **容器猜错就换一种建源方式重试一次**。真猜错时 ExoPlayer 报的是「容器不支持」，这时把 HLS 与直链互换、从原进度重来一次，比直接弹「播不了」有用得多。只换一次，换完还失败才是真播不了；只对解析类错误换，编解码器不支持这类换了也白换。
- **失败提示带上底层原因**。原来只有 `ERROR_CODE_IO_BAD_HTTP_STATUS` 这种干巴巴的错误码，现在补上最内层那句真实原因（HTTP 状态码、解封装失败的具体位置），真出问题时能直接拿去搜。

**没有改成「一律不带 Referer」**：那会把另一批站点的播放弄坏，而这批站点当初正是为了它们才带上 Referer 的。两种站点都存在，所以只能先试一种、被拒了再退。

### 上一轮（1.8）：下载看得见进度，视频站的前贴片广告能去掉

两个需求，一个关于「看得见」，一个关于「看不见」。

**下载要显示速度、总大小、已下载多少。** 三个数字里有两个 Media3 不直接给：

- **总大小**：`Download.contentLength` 在 media3 1.4.1 里恒为 `C.LENGTH_UNSET`——`DownloadManager` 构造 `Download` 时就把这个字段写死成 -1，`DownloadProgress` 里也只剩「已下载字节」和「完成比例」（反编译确认过）。HLS 的分片长度本来就要下完才知道。所以总大小是从「已下载 ÷ 已完成比例」反推的，标「约」；比例低于 1% 时干脆不报，那时候的估算会往下缩，比不报更让人困惑。
- **速度**：只能自己采样——两次「已下载字节」的差除以时间差。几个边界得钉死：样本不足时返回 0（「还不知道」和「0 速度」是两种说法，界面上写「0 B/s」看起来像卡住了）；字节不变时不记样本，否则「原地不动」的时间会把已有进度摊薄成一个假的慢速度；字节倒退（删掉重下、换源）时把旧样本全部作废，不然会算出负数。
- 顺带修了一个真问题：**下载页以前不会自己刷新**，进度、已下载字节都停在打开那一刻。现在页面开着时每 0.5 秒刷一次，只在真有东西在跑时才查库。

**去视频前贴片广告。** 样本是你给的 `4kvm.net`。先把站点拆开看：ArtPlayer + 官方 `artplayer-plugin-ads`，播放器容器上写着

```
data-preroll-ad-type="image"  data-preroll-ad-duration="12"  data-preroll-ad-skip-after="6"
```

也就是「图片广告放 12 秒，6 秒后才允许关」。这决定了拦在哪一层：

- **只拦域名没用**。这类广告是站点自己的页面元素，广告图在站点的图片 CDN 上，和正文图片同域——拦域名等于把正文图片一起拦掉，广告却照放，只是变成一个破图。
- **注入脚本三层处理**（`AdBlockScript`，从最干净到兜底）：① 剥掉 `data-preroll-ad*` 属性，站点那段代码拿不到广告配置，插件根本不会装，一秒广告都不放；② 用 setter 拦下 `window.artplayerPluginAds`，站点读到的是空壳（它先做 `typeof` 判断再调用，所以空壳得是个函数）——这一层不看时序，注入晚了也有效；③ 前两层都没赶上时，把 `.artplayer-plugin-ads` 浮层摘掉，**并且把正片播回来**——插件的做法是「暂停正片再盖广告」，只删浮层会让用户看到「广告没了，画面也不动了」。
- ①要赢在时序上，所以脚本在 `onPageStarted` 就注入，不再等 `onPageFinished`（那时页面脚本早把属性读走了）。这是「尽量早」而不是保证，`onPageFinished` 那次和脚本自身的 MutationObserver + 轮询是兜底。
- 域名名单同时补了视频贴片广告网络（FreeWheel、SpotX、Teads、SpringServe 等 32 条，共 67 条）。**故意不拦 `imasdk.googleapis.com`**——它是 Google IMA 的播放器 SDK，拦掉会让用它的播放器整个起不来，代价比多看几秒广告大。这条取舍在单测里钉住了。
- 顺手修了 Lint 唯一一条来自自己代码的告警：进小窗时把画面位置交给系统（`setSourceRectHint`），否则小窗动画会从屏幕中央长出来。

**验证状态**：当轮 340 例单元测试全绿、Lint 无 error。**真机实测这一轮仍然没跑**——那台模拟器被外部自动化脚本反复强杀应用。去广告这一条尤其需要你在真机上确认：注入时机是个竞态，最坏情况是广告闪一下再消失（而不是完全不出现），我按「三层叠加」写的，但只有真机能给出最终答案。

### 上一轮（1.7）：控制层按单手位置重排，补上小窗 / 投屏 / 下载

上一轮把控制层做出来之后，真机上试用的反馈是位置不顺手，要的功能也没齐。这一轮只动播放器：

- **位置重排**（按单手能够到的位置放）：**右上角**「小窗 / 投屏」——两个都是「把画面交出去」的动作；**右侧中间**「下载」——单独占一列，不与中间的播放键抢位置；**右下角**一排「倍速 · 画质 · 适应 · 退出全屏」——拇指自然落点。中间留播放/暂停与 ±10 秒，底部是进度条。
- **小窗播放**：`PlayerActivity` 打开 `supportsPictureInPicture`，点「小窗」把画面缩成画中画继续播。宽高比先按系统允许的区间（1/2.39–2.39）夹紧——竖屏短剧的比例会越界，越界时系统直接抛异常，真机上表现就是「点了没反应」。小窗里控制层与手势整层让开，否则会盖住系统自己的展开/关闭按钮。
- **投屏**：把正在播的地址交给能接视频通配 MIME 的应用，与网页浮层的投屏走同一条路，不引入 Google Cast。
- **下载**：直链交给系统下载器、HLS 进离线缓存。这条分岔以前在网页侧写了一遍，现在抽成 `MediaDownload` 给网页浮层、主菜单、内置播放器三处共用——真的漂移过一次，把 `.m3u8` 交给系统下载器，用户拿到一个几 KB 的文本文件。
- 顺手把 `DownloadRequest` 从 UI 层挪到 `data` 层：它本来就是给 `DownloadsRepository` 用的 DTO，之前是数据层反过来依赖界面层。

**验证状态**：311 例单元测试全绿、Lint 无 error。真机/模拟器实测这一轮仍然没跑（那台模拟器被外部自动化脚本反复强杀应用），小窗与投屏这两条尤其需要你在真机上确认——小窗受系统与 ROM 影响最大。

### 上一轮（1.6）：把播放器的「能看」补成「好用」

1.5 解决了「全屏黑屏」和「没有下载按钮」，装到真机上试完之后反馈是**「播放效果不太好」**。问下来具体是三条：卡顿/一直缓冲、画质糊/不能切清晰度、操作太少（手势/倍速/记忆进度）。这三条都不是引擎选错了——ExoPlayer 的 HLS 支持已经是这几个候选里最完整的，缺的是控制层和参数。所以这一轮没有换引擎，也没加新依赖：

- **卡顿**：打开硬解失败自动回退软解（`setEnableDecoderFallback(true)`，vivo / OPPO / 部分联发科机型上硬解初始化失败会直接报错退出，这是「有些视频播不了」最常见的成因）；缓冲从默认值放宽到 **20 秒起播 / 60 秒上限 / 起播前最少 2.5 秒**，弱网下不再一卡就重新缓冲；HLS 打开 chunkless 预解析，起播时不必先把整张分片清单拉下来才知道有几档。
- **画质与清晰度**：`master.m3u8` 本来就带好几档码率，ExoPlayer 默认自动选（网差时自己降档，这是对的），但用户看不到「现在是多少」也改不了。现在从 `Tracks` 里读出各档，整理成「1080P / 720P / 480P」这类标签，点一下给视频轨设一条覆盖，也可以点「自动」交回去。同一清晰度有多条轨道（avc1 与 hevc）时只留码率最高的那条，否则面板上会出现一排「1080P」。
- **操作**：自己画了一套控制条（ExoPlayer 自带的没有清晰度、没有倍速、没有画面比例，也不跟应用的深色令牌一致）——进度拖动、±10 秒、**倍速 0.5×–3×**、**画面比例**（适应/铺满/裁剪）。手势按国内视频 App 的习惯：**左半屏上下滑调亮度、右半屏调音量、横向拖看进度（拖动中只预览，抬手才跳）、双击左右半屏进退 10 秒**。**播放进度与倍速都记住**，下次接着看——「看到第 3 秒就退出」和「已看到结尾」这两种情况不记，否则下次「接着播」比从头播还烦。
- 清晰度、倍速、手势方向、时间格式这些判断都抽成了纯函数（`PlayerGestures` / `PlayerQuality` / `MediaUrls` / `PlaybackPreferences`），所以能单测。**写这批测试时抓到三个真 bug**：码率按 kb 而不是 bit 换算（1.2 Mbps 显示成 1200.0 Mbps）、540P 被套成「480P」、拖动位移的分钟位不补零（`+1:20` 而不是 `+01:20`）。

**验证状态**：306 例单元测试全绿、Lint 无 error。真机/模拟器实测这一轮仍然没跑（那台模拟器被外部自动化脚本反复强杀应用），所以「不卡了」「能切清晰度了」这些结论目前只有单元测试与代码路径的保证，麻烦你在 iQOO Z11x 上再试一次。

### 上一轮（1.5）：全屏改走内置播放器，流媒体能离线了

起因是真机（iQOO Z11x）上的反馈：**「全屏之后是黑屏，而且没有下载按钮」**，站点是欧乐影院（`olevod.com`）。先把这个站点拆开看了一遍，两条症状是同一个根因：

- 页面是 Vue SPA + plyr + hls.js，页面里那个 `<video>` 的 `src` 是 `blob:`（MSE 壳子），真实流只出现在网络层：`master.m3u8` → `index-v1-a1.m3u8` → `seg-N-v1-a1.ts`（每片 10 秒）。
- 站点**没有直链 mp4**（直接请求 `.mp4` 路径返回 HTTP 400）。所以「存成一个单文件」在这类站点上不可能，除非自己把分片拼起来。

于是 1.5 换掉了整条媒体链路（详细设计见规格 5.13）：

- **全屏不再交给 WebView**。以前是 `WebChromeClient.onShowCustomView` 把播放 View 交出来、由应用搬到窗口上——这条路在真机上是黑的（模拟器却正常）。现在「全屏」把嗅探到的真实流地址和当前进度交给 `PlayerActivity`（Media3 / ExoPlayer + `PlayerView`），用原生 Surface 渲染，HLS 直接能播，横屏、沉浸式、返回键退出都由自己控制。
- **新增网络层嗅探** `MediaSniffer`：挂在 `shouldInterceptRequest` 上按标签记录媒体地址，播放列表（`.m3u8` / `.mpd`）优先、直链文件次之、分片（`.ts` / `.m4s` / `.aac`）忽略；取用时优先 `master.m3u8`（让播放器自己选码率）；换页清空。
- **浮层三个按钮总是都在**。1.4 在 `blob:` 源上只给「全屏」，用户看到的就是「没有下载按钮」——按钮缺席像是功能没做。现在按钮照给，解析不出地址时给一句提示说明原因。
- **下载分流**：播放列表进 Media3 的离线缓存（`SimpleCache` + 前台 `DownloadService`，切走应用不会被系统收走），直链文件仍交给系统 `DownloadManager`。播放与离线共用同一份缓存，下完就是真离线可播。下载页把两个来源合成一张列表，离线条目标「离线缓存」，点开进内置播放器。
- **投屏**不变：仍是拿到解析后的地址走 `ACTION_CHOOSER` + `video/*`，不引入 Google Cast。

**验证状态**：269 例单元测试全绿、Lint 无 error、签名 release APK 已产出（签名证书 SHA-256 与 1.0–1.4 一致，可覆盖升级）。**真机/模拟器实测这一轮没跑**——欧乐影院那台模拟器被外部自动化脚本反复强杀应用，装上去也活不过 6 秒，所以「全屏不黑」「离线缓存真的下完」这两条目前只有单元测试与代码路径的保证，等你在真机上试。

### 上一轮（1.4）在模拟器上确认的改动

这一轮起因是真机上的三条反馈：视频页面上要能直接下载和投屏、全屏还是不生效、下载与历史会闪退。四条都在自建页面上跑过（页面里两个 `<video>`：一个挂 `media.mp4` + `media.webm`，一个用 `MediaSource` 喂 `blob:`）：

- **视频浮层**：两个视频右上角都出现了浮层。普通源那条是「全屏 / 下载 / 投屏」三个按钮，blob 那条只剩「全屏」。点「下载」后 `DownloadManager` 记 `Finished with status SUCCESS`，应用没闪退；点「投屏」由本应用发起 `ACTION_CHOOSER` + `video/*`，系统选择器正常弹出。
- **全屏**：点浮层「全屏」后界面切到横屏 1920×1080，视频铺满整屏、状态栏与导航栏一并隐藏；按返回键退出全屏并恢复竖屏，页面和浮层都还在。
- **下载闪退修好了**：blob 页面上点菜单「下载视频」不再闪退，改成提示「本页视频是 blob/MSE 流式地址，浏览器取不到文件」。
- **历史**：书签与历史页正常渲染出两条记录，没有闪退。

### 这一轮在模拟器上发现并修掉的缺陷

| 缺陷 | 根因 |
|---|---|
| 浮层注进去了、坐标也对，但页面上什么都看不见 | 按钮和浮层共用了同一个标记属性 `data-aurora-media`；回收孤儿浮层的循环正是按这个属性查，而按钮身上没有 `__owner`，于是每个按钮都被判成孤儿当场删掉，页面上只剩两个 0×0 的空壳。按钮改用独立的 `data-aurora-media-btn` |
| 点浮层「下载」在 blob 页面上闪退 | `DownloadManager.Request` 的**构造函数**就拒绝非 http/https 地址（`Can only download HTTP/HTTPS URIs`），而旧的守卫只包住了 `enqueue()`。现在整段入队都包在 `runCatching` 里，并且先把 `blob:`/`data:` 源过滤掉 |
| 竖屏下全屏，横屏视频只占中间一条 | 全屏时没切方向。现在进全屏把 Activity 掰到横屏（`SENSOR_LANDSCAPE`），退出时恢复原方向 |
| 真机上全屏不生效（模拟器却正常） | 系统栏隐藏本身会改变 `screenLayout` / `smallestScreenSize` 等配置，`configChanges` 没列全就会重建 Activity，刚挂上去的全屏 View 连同页面一起没了。补齐 `configChanges`，并把旧版 `systemUiVisibility` 标志位与 insets controller 一起点——国内 ROM 对这两条路的响应并不一致 |

**真机崩溃复现不了时的兜底**：新增 `CrashLog`，未捕获异常立刻写进 `SharedPreferences`，下次启动弹「上次崩溃了」对话框，可一键复制堆栈。用户报的「点历史闪退」在模拟器上始终复现不出来（历史页正常渲染，两条记录都在），所以顺手把历史按 URL 去重、列表 key 改成唯一值，再把这个对话框装上——下次真出问题就不用靠猜了。

### 上一轮（1.3）在模拟器上确认的四个改动

四项都在自建页面上跑通，页面里放了两个 `<video>`（一个挂 `media.mp4` + `media.webm` 两个 `<source>`，一个用 `MediaSource` 喂 `blob:` 地址）和一个 `requestFullscreen()` 按钮：

- **主页不再有「为你推荐」**：快捷入口网格下方直接是空白，设置页也没有了对应的「主页信息流」开关。
- **视频真全屏**：点「进入全屏」后内容铺满整块 1080×1920，状态栏与导航栏一并隐藏；按返回键退出全屏并留在原页面，不会连带后退一步。
- **视频下载**：2 个 `<source>` + 1 个 `blob:` 被正确提取；选 `media.mp4` 后 `/sdcard/Download/media.mp4` 大小 98304 字节，与源文件一致；`blob:` 那行标成「不支持」且点不动。
- **投屏**：面板分「屏幕镜像」与「投屏播放视频」；屏幕镜像经 `android.settings.CAST_SETTINGS` 打开系统投屏页（模拟器显示「未在附近找到设备」）；投屏播放视频列出同一批视频源，本机没有应用声明 `video/*` 时给出「没有能投屏播放该视频的应用」，不崩也不假装成功。

### 上一轮（1.3）发现并修掉的缺陷

| 缺陷 | 根因 |
|---|---|
| 网页视频点全屏只是把画面拉大，状态栏和地址栏都还在 | 没实现 `WebChromeClient.onShowCustomView` / `onHideCustomView`：WebView 的全屏请求没有宿主接管，视频只能停在原来的内联位置 |
| 视频没有下载入口 | HTML5 `<video>` 是内联渲染的，`DownloadListener` 根本不会触发；只能注入 JS 进页面里找 `<video>` / `<source>` 的地址 |
| blob/MSE 视频源在列表里显示成三行随机 UUID | `labelOf` 把 `blob:` 的路径当文件名用，而那段路径是会话 UUID；改成固定显示「流式视频」+「blob 地址 · 无法下载」 |

### 更早（1.2）发现并修掉的缺陷

| 缺陷 | 根因 |
|---|---|
| 地址栏「粘贴并前往」被裁成「粘贴并前」 | 快捷动作标签没指定字号，落到默认 `bodyLarge`(16sp)，窄屏四个等宽块放不下 |
| 长页面滚到底时最后一行永久停在悬浮工具栏底下 | 工具栏浮在网页之上，而网页文档末尾没有留白；改成注入一段尾部滚动空间（对齐原型 `.page{padding-bottom:110px}`） |
| 收藏星标点完不变色，要等别的操作触发重组才补上 | `vm.isBookmarked()` 内部读 `StateFlow.value`，组合期读不出订阅；改用已 `collectAsState` 的列表判断 |
| 设置页与隐私页的页头（含唯一的应用内返回入口）会跟着内容滚走 | 这两个界面的 `ScreenHeader` 被放进了滚动容器内；书签/下载/阅读三个界面一直是固定的，只有这两个漏了 |
| 标签列表视图里新标签页的标题和副标题都是「新标签页」 | 副标题在地址为空时兜底成「新标签页」，与标题重复；改为无地址就不画副标题 |

## 构建

需要 JDK 17+ 与 Android SDK（compileSdk 35）。

```bash
# 单元测试
./gradlew :app:testDebugUnitTest

# Lint
./gradlew :app:lintDebug

# 调试包
./gradlew :app:assembleDebug

# 发布包（需提供签名配置，见下）
./gradlew :app:assembleRelease
```

发布包签名通过根目录的 `keystore.properties`（已 gitignore）注入，缺失时 release 构建产出未签名 APK：

```properties
storeFile=.signing/aurora-release.jks
storePassword=******
keyAlias=aurora
keyPassword=******
```

图标由 `node tools/phosphor_to_drawable.mjs` 生成（需要联网）。脚本会先校验自己的名单与 `AuroraIcons.kt` 的 `byName` 一致，不一致直接失败；生成后清掉不在名单里的旧 drawable。
