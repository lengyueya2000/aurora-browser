# Aurora Browser（极光浏览器）

一款「全能功能型」安卓浏览器：在单手可及的界面上，把标签管理、拦截、阅读、下载、书签这些能力收进一个克制的深色界面里。

- **技术栈**：Kotlin + Jetpack Compose（Material 3）+ Android WebView
- **平台**：Android 8.0+（API 26+），targetSdk 35
- **视觉**：现代简约 · 深色优先（Dark Mode / OLED）

| 分享 | 系统分享面板分享当前网址 |

## 明确没做的

这些不是「以后再说」，而是当前版本确实没有的能力，写在这里免得装完才发现：

- **扩展**：Android WebView 没有扩展 API，`.crx`/`manifest.json` 那套只存在于桌面 Chromium。这不是排期问题，是平台不支持，所以菜单里没有扩展入口。
- **Chromecast 原生投屏**：没有接入 Google Cast SDK。它要求注册 Cast app id 并依赖 Google Play 服务，在没有 GMS 的设备上直接不可用，还会把闭源依赖引进来。也试过 `androidx.mediarouter` 的设备选择器，但它的 `MediaRouteChooserDialog` 继承 `AppCompatDialog`，要整个应用套上 AppCompat 主题——对一个纯 Compose 应用来说是为一颗按钮换掉主题体系，不划算，于是改成零依赖实现：屏幕镜像交给系统的投屏页，视频交给能播 `video` 通配 MIME 的应用（各类投屏播放器都在此列）。
- **逐站权限授权**：相机 / 麦克风 / 定位当前一律拒绝，没有「本站允许」的授权弹窗。唯一的例外是 DRM 的 protected media id——全屏播放加密流要用，且不是用户可见权限。
- **标签持久化**：进程被系统回收后标签页不会恢复，重启是全新一个标签页。
- **HLS 不能存成一个 mp4 文件**：这类站点（欧乐影院、各类影视站）只给 `.m3u8` 分片清单，没有直链 mp4。所以「下载」给的是应用内离线缓存——在下载页能看到、能打开、能离线播，但不会在文件管理器里出现一个 mp4。想要单文件得自己写 HLS 下载器再把分片拼起来，这一版没做。
- **同步、账号、查找页内文字、桌面模式、翻译、拦截规则在线更新**：都没有。
- **明文 HTTP 是放行的**：这是个浏览器，打不开 `http://` 站点等于不能用；地址栏的「不安全」标识负责提醒。

## 验证到什么程度

- **单元测试 269 例全绿**（JUnit + Robolectric + Compose UI Test），覆盖状态机、标签仓库、地址栏解析与建议、书签/历史/下载仓库、追踪拦截名单、WebView 池与容器、视频全屏控制器（含真实宿主的方向恢复）、视频源提取、媒体浮层脚本与桥的准入校验、媒体地址嗅探（播放列表优先、分片忽略、按标签隔离与换页清空）、离线缓存列表、投屏入口，以及全部界面。
- **每个测试类跑在独立 JVM 里**（`forkEvery = 1`）。Robolectric 按 `@Config` 复用沙箱，Compose 测试留下的组合会让同一批里后面的 Compose 测试永远等不到 idle（`AppNotIdleException`，单独跑却全绿）——隔离之后 31 个假失败一起消失，剩下的是真结果。
- **Lint 无 error**：47 条 warning 全部与业务代码无关——36 条依赖有新版本（Media3 也贡献了 4 条）、3 条 AGP 版本提示、2 条 `commit()` 写偏好（崩溃日志要的就是立刻落盘）、2 条 `-v26` 限定符冗余、1 条 targetSdk 未追到最新、1 条 `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES` 是 API 28 常量（有运行时判断兜着）、2 条图标矢量路径偏长。
- **在雷电模拟器（Android 14 / API 34，1080×1920）上完整跑过一遍**：主页与快捷入口、关键词搜索落到搜索结果页、地址栏网址识别、书签星标与书签/历史库、菜单入口、阅读模式正文提取、隐私面板拦截计数、设置全部开关、无痕标签隔离与提示条、标签网格/列表、下载落盘与打开、系统分享面板。下面这些「只有真机才能验」的路径**已经在模拟器上确认可用**：下载落盘（文件确实进了 `/sdcard/Download/`，点开能唤起系统看图应用）、阅读模式正文提取（导航栏与广告位被剔除）、无痕隔离（顶部提示条 + 独立 WebView）、追踪器拦截（自建页面发起的 4 个请求里命中名单的 3 个被拦下，不在名单里的 1 个放行）。
- **仍未验证的**：语音搜索与扫码需要真机的语音/扫码应用（模拟器里没有，代码路径会走到「没有可用的扫码应用」提示）；相机/麦克风/定位授权当前一律拒绝，没有逐站授权可测；长按与边缘滑动返回手势没有自动化手段，只做了人工点击验证；投屏只能验到「系统投屏页能打开、无接收端时给出提示」——模拟器里没有电视可投，真实投屏画面没法验。

### 这一轮（1.5）：全屏改走内置播放器，流媒体能离线了

起因是真机（iQOO Z11x）上的反馈：**「全屏之后是黑屏，而且没有下载按钮」**，站点是欧乐影院（`olevod.com`）。先把这个站点拆开看了一遍，两条症状是同一个根因：

- 页面是 Vue SPA + plyr + hls.js，页面里那个 `<video>` 的 `src` 是 `blob:`（MSE 壳子），真实流只出现在网络层：`master.m3u8` → `index-v1-a1.m3u8` → `seg-N-v1-a1.ts`（每片 10 秒）。
- 站点**没有直链 mp4**（直接请求 `.mp4` 路径返回 HTTP 400）。所以「存成一个单文件」在这类站点上不可能，除非自己把分片拼起来。

于是 1.5 换掉了整条媒体链路（详细设计见规格 5.13）：

- **全屏不再交给 WebView**。以前是 `WebChromeClient.onShowCustomView` 把播放 View 交出来、由应用搬到窗口上——这条路在真机上是黑的（模拟器却正常）。现在「全屏」把嗅探到的真实流地址和当前进度交给 `PlayerActivity`（Media3 / ExoPlayer + `PlayerView`），用原生 Surface 渲染，HLS 直接能播，横屏、沉浸式、返回键退出都由自己控制。
- **新增网络层嗅探** `MediaSniffer`：挂在 `shouldInterceptRequest` 上按标签记录媒体地址，播放列表（`.m3u8` / `.mpd`）优先、直链文件次之、分片（`.ts` / `.m4s` / `.aac`）忽略；取用时优先 `master.m3u8`（让播放器自己选码率）；换页清空。
- **浮层三个按钮总是都在**。1.4 在 `blob:` 源上只给「全屏」，用户看到的就是「没有下载按钮」——按钮缺席像是功能没做。现在按钮照给，解析不出地址时给一句提示说明原因。
- **下载分流**：播放列表进 Media3 的离线缓存（`SimpleCache` + 前台 `DownloadService`，切走应用不会被系统收走），直链文件仍交给系统 `DownloadManager`。播放与离线共用同一份缓存，下完就是真离线可播。下载页把两个来源合成一张列表，离线条目标「离线缓存」，点开进内置播放器。
- **投屏**不变：仍是拿到解析后的地址走 `ACTION_CHOOSER` + `video/*`，不引入 Google Cast。

**验证状态**：269 例单元测试全绿、Lint 无 error、签名 release APK 已产出（签名证书 SHA-256 与 1.0–1.4 一致，可覆盖升级）。**真机/模拟器实测这一轮没跑**——欧乐影院那台模拟器被外部自动化脚本反复强杀应用，装上去也活不过 6 秒，所以「全屏不黑」「离线缓存真的下完」这两条目前只有单元测试与代码路径的保证，等你在真机上试。

### 上一轮（1.4）在模拟器上确认的改动

这一轮起因是真机上的三条反馈：视频页面上要能直接下载和投屏、全屏还是不生效、下载与历史会闪退。四条都在自建页面上跑过（页面里两个 `<video>`：一个挂 `media.mp4` + `media.webm`，一个用 `MediaSource` 喂 `blob:`）：

- **视频浮层**：两个视频右上角都出现了浮层。普通源那条是「全屏 / 下载 / 投屏」三个按钮，blob 那条只剩「全屏」。点「下载」后 `DownloadManager` 记 `Finished with status SUCCESS`，应用没闪退；点「投屏」由本应用发起 `ACTION_CHOOSER` + `video/*`，系统选择器正常弹出。
- **全屏**：点浮层「全屏」后界面切到横屏 1920×1080，视频铺满整屏、状态栏与导航栏一并隐藏；按返回键退出全屏并恢复竖屏，页面和浮层都还在。
- **下载闪退修好了**：blob 页面上点菜单「下载视频」不再闪退，改成提示「本页视频是 blob/MSE 流式地址，浏览器取不到文件」。
- **历史**：书签与历史页正常渲染出两条记录，没有闪退。

### 这一轮在模拟器上发现并修掉的缺陷

| 缺陷 | 根因 |
|---|---|
| 浮层注进去了、坐标也对，但页面上什么都看不见 | 按钮和浮层共用了同一个标记属性 `data-aurora-media`；回收孤儿浮层的循环正是按这个属性查，而按钮身上没有 `__owner`，于是每个按钮都被判成孤儿当场删掉，页面上只剩两个 0×0 的空壳。按钮改用独立的 `data-aurora-media-btn` |
| 点浮层「下载」在 blob 页面上闪退 | `DownloadManager.Request` 的**构造函数**就拒绝非 http/https 地址（`Can only download HTTP/HTTPS URIs`），而旧的守卫只包住了 `enqueue()`。现在整段入队都包在 `runCatching` 里，并且先把 `blob:`/`data:` 源过滤掉 |
| 竖屏下全屏，横屏视频只占中间一条 | 全屏时没切方向。现在进全屏把 Activity 掰到横屏（`SENSOR_LANDSCAPE`），退出时恢复原方向 |
| 真机上全屏不生效（模拟器却正常） | 系统栏隐藏本身会改变 `screenLayout` / `smallestScreenSize` 等配置，`configChanges` 没列全就会重建 Activity，刚挂上去的全屏 View 连同页面一起没了。补齐 `configChanges`，并把旧版 `systemUiVisibility` 标志位与 insets controller 一起点——国内 ROM 对这两条路的响应并不一致 |

**真机崩溃复现不了时的兜底**：新增 `CrashLog`，未捕获异常立刻写进 `SharedPreferences`，下次启动弹「上次崩溃了」对话框，可一键复制堆栈。用户报的「点历史闪退」在模拟器上始终复现不出来（历史页正常渲染，两条记录都在），所以顺手把历史按 URL 去重、列表 key 改成唯一值，再把这个对话框装上——下次真出问题就不用靠猜了。

### 上一轮（1.3）在模拟器上确认的四个改动

四项都在自建页面上跑通，页面里放了两个 `<video>`（一个挂 `media.mp4` + `media.webm` 两个 `<source>`，一个用 `MediaSource` 喂 `blob:` 地址）和一个 `requestFullscreen()` 按钮：

- **主页不再有「为你推荐」**：快捷入口网格下方直接是空白，设置页也没有了对应的「主页信息流」开关。
- **视频真全屏**：点「进入全屏」后内容铺满整块 1080×1920，状态栏与导航栏一并隐藏；按返回键退出全屏并留在原页面，不会连带后退一步。
- **视频下载**：2 个 `<source>` + 1 个 `blob:` 被正确提取；选 `media.mp4` 后 `/sdcard/Download/media.mp4` 大小 98304 字节，与源文件一致；`blob:` 那行标成「不支持」且点不动。
- **投屏**：面板分「屏幕镜像」与「投屏播放视频」；屏幕镜像经 `android.settings.CAST_SETTINGS` 打开系统投屏页（模拟器显示「未在附近找到设备」）；投屏播放视频列出同一批视频源，本机没有应用声明 `video/*` 时给出「没有能投屏播放该视频的应用」，不崩也不假装成功。

### 上一轮（1.3）发现并修掉的缺陷

| 缺陷 | 根因 |
|---|---|
| 网页视频点全屏只是把画面拉大，状态栏和地址栏都还在 | 没实现 `WebChromeClient.onShowCustomView` / `onHideCustomView`：WebView 的全屏请求没有宿主接管，视频只能停在原来的内联位置 |
| 视频没有下载入口 | HTML5 `<video>` 是内联渲染的，`DownloadListener` 根本不会触发；只能注入 JS 进页面里找 `<video>` / `<source>` 的地址 |
| blob/MSE 视频源在列表里显示成三行随机 UUID | `labelOf` 把 `blob:` 的路径当文件名用，而那段路径是会话 UUID；改成固定显示「流式视频」+「blob 地址 · 无法下载」 |

### 更早（1.2）发现并修掉的缺陷

| 缺陷 | 根因 |
|---|---|
| 地址栏「粘贴并前往」被裁成「粘贴并前」 | 快捷动作标签没指定字号，落到默认 `bodyLarge`(16sp)，窄屏四个等宽块放不下 |
| 长页面滚到底时最后一行永久停在悬浮工具栏底下 | 工具栏浮在网页之上，而网页文档末尾没有留白；改成注入一段尾部滚动空间（对齐原型 `.page{padding-bottom:110px}`） |
| 收藏星标点完不变色，要等别的操作触发重组才补上 | `vm.isBookmarked()` 内部读 `StateFlow.value`，组合期读不出订阅；改用已 `collectAsState` 的列表判断 |
| 设置页与隐私页的页头（含唯一的应用内返回入口）会跟着内容滚走 | 这两个界面的 `ScreenHeader` 被放进了滚动容器内；书签/下载/阅读三个界面一直是固定的，只有这两个漏了 |
| 标签列表视图里新标签页的标题和副标题都是「新标签页」 | 副标题在地址为空时兜底成「新标签页」，与标题重复；改为无地址就不画副标题 |

## 下载

从 [Releases](https://github.com/lengyueya2000/aurora-browser/releases) 下载 `aurora-browser-1.5-release.apk` 直接安装（需允许「安装未知来源应用」）。与 1.0 / 1.1 / 1.2 / 1.3 / 1.4 使用同一签名，可直接覆盖升级。

## 构建

需要 JDK 17+ 与 Android SDK（compileSdk 35）。

```bash
# 单元测试
./gradlew :app:testDebugUnitTest

# Lint
./gradlew :app:lintDebug

# 调试包
./gradlew :app:assembleDebug

# 发布包（需提供签名配置，见下）
./gradlew :app:assembleRelease
```

发布包签名通过根目录的 `keystore.properties`（已 gitignore）注入，缺失时 release 构建产出未签名 APK：

```properties
storeFile=.signing/aurora-release.jks
storePassword=******
keyAlias=aurora
keyPassword=******
```
